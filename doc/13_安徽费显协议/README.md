# 13 安徽费显协议

> 安徽费显协议（2026-S304 费显通信协议，费显标准协议，2026-09 接入）接入记录。
> 模块：`Application/Src/ProtocolParser_Anhui/` + `Application/Inc/ProtocolParser_Anhui/`（前缀 `anhui_`，文件前缀 `app_anhui_proto_`；命名避开 `ah_`——AH_MQTT 已占用 `ah_mqtt`）。

## 1. 协议事实（12 命令）

帧格式：`5A`(起始) + 屏号(1B，本设备 01) + 命令(1B) + 数据长(1B 二进制) + 数据(变长) + CRC(1B) + `A5`(结束符)。帧总长 = 数据长 + 6，数据长 1 字节上限 255 → 整帧 ≤ 261。**CRC 字段协议文档注明「无检验，默认为 0」→ 不校验**。传输：串口（RS232/RS485），协议文档未指定波特率 → 沿用 DIP1 统一选择（9600/115200，8N1）。文本编码：协议标注 ANSI（中文 Windows 语境即 GBK），渲染 `FONT_ENC_GBK` 直通。


| 命令            | 名称           | 参数约束（最终实现）                                                                                     | 行为                                                                                      |
| ------------- | ------------ | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `0x81`        | 清屏           | 数据长==0                                                                                         | 整屏黑 + commit                                                                            |
| `0x82`        | 显示点          | 数据长==2；X(1B) Y(1B)；坐标范围以实际屏幕尺寸为准（文档 128×64 不作为标准，§8 决定 8 已裁决）                          | 单像素点亮（默认红色，§8 决定 2 待确认）+ commit                                                         |
| `0x83`        | 关闭点          | 数据长==2；坐标范围以实际屏幕尺寸为准（§8 决定 8）                                                                 | 单像素熄灭 + commit                                                                          |
| `0x85`        | 静态显示         | 数据长==2+文本；X Y + 文本(GBK)；坐标范围以实际屏幕尺寸为准（§8 决定 8）                                                    | 按 X/Y 坐标 FONT_16 渲染，单行不换行、超宽截断；文本前不清行（文档未要求）                                            |
| `0x86`~`0x89` | 动态显示 第 1~4 行 | 数据长≥4：运动模式(1B)+速度(1B ×2ms)+停留时间(2B ×100ms)+文本；停止帧=数据长 4 且四字节全 0                                | **留空（TODO 占位，已裁决 2026-09-04 继续留空）**：解析校验后不执行，见 §7                                                        |
| `0x92`        | 设置亮度         | 数据长==2；亮度参数 2B 大端，最大 0x03E7(999)                                                               | 0=恢复光敏自动调光；1~999=挂起光敏 + 均匀映射 8 档 1~8（`level = 1 + value*7/999`，§8 决定 4 已裁决 2026-09-04）                            |
| `0x94`        | 设置通行灯/报警器    | 数据长==2；类型(01=通行灯,02=报警器) + 参数(00=灭/关,01=亮/开)                                                   | 通行灯→`dev_io_lane_light`；报警器→`dev_io_flash_light`（黄闪灯，§8 决定 5 待确认）                       |
| `0x95`        | 播放声音         | 数据长≥3；语音编号(2B ASCII 01~15) + 音量(1B ASCII '0'~'9') + 参数（编号 01~14 = 变长 ASCII；编号 15 = 全部播报内容 GBK） | 编号 01~14：14 个模板句构造 → TTS 语音板（§2）；编号 15：参数区即全部播报内容（GBK 自由文本）原样透传语音板（超 200B 截断）；**音量字节解析保留、执行层忽略**（语音板不支持协议调音量，§8 决定 9 已裁决） |
| `0x96`        | 播放录制语音       | 数据长==2；段号(2B ASCII 数字)                                                                         | **占位**：语音板无段号播报接口（§7）                                                                   |
| `0x97`        | 录制语音         | 数据长==2；段号(2B ASCII 数字)                                                                         | **占位**：语音板无段号录制接口（§7）                                                                   |


应答：**协议文档未定义任何应答 → 单向不回**（对齐青海单向模式）。

## 2. 语音模板句（0x95，文档原文 14 条 + 编号 15 自由文本）


| 编号    | 模板句                                                         | 参数                                |
| ----- | ----------------------------------------------------------- | --------------------------------- |
| 01    | 你好，几型车，您应交多少元                                               | 车型(1B) + 金额(7B)                   |
| 02    | 你好，几型车，总重多少吨，您应交多少元                                         | 车型(1B) + 重量(4B) + 金额(7B)          |
| 03    | 总重多少吨，超重多少吨                                                 | 重量(4B) + 超重(4B)                   |
| 04    | 几型车，收费多少元                                                   | 车型(1B) + 金额(7B)                   |
| 05    | 某某（用户类型），几型,收费多少元                                           | 用户类型(1B) + 车型(1B) + 金额(7B)        |
| 06    | 某某卡，某某（用户类型），收费多少元                                          | 卡片类型(1B) + 用户类型(1B) + 金额(7B)      |
| 07    | 余额多少元                                                       | 金额(7B)                            |
| 08~14 | 您好，免费车 / 您好 / 谢谢 / 谢谢合作，走好 / 再见 / 谢谢，祝您一路平安 / 谢谢，雨雪雾天行车注意安全 | 无                                 |
| 15    | （自由文本播报，非模板句）                                               | 参数区即全部播报内容（GBK 原样透传语音板，超 200B 截断） |


编码表（文档原文）：金额 = 7 字节 ASCII「千百十个.角分」（如「1030.42」）；车型 1B ASCII（0x31 一型车…0x30 不播车型）；重量 4B ASCII；用户类型 0x30 正常车/0x31 免费车/0x32 军警车/0x33 公务车/0x34 公交专线车；卡片类型 0x30 储值卡/0x31 记账卡。

**金额读数按文档示例转换**：「1030.42」→「一千零三十点四二元」；小数部分「00」不播（「1030.00」→「一千零三十元」）；「.40」→「点四」、「.02」→「点零二」（§8 决定 3）。整数读数规则：前导零不读、中间零读一次「零」、十位起首 1 不读「一」（「10」→「十」）。重量/超重用同一整数读法（文档未定义，§8 决定 6 待确认）。

**编号 15（自由文本播报，设备扩展）**：参数区即全部播报内容（协议 ANSI = GBK），不套模板句，原样透传 `dev_rs232_voice_play`（TTS 语音板，与 CQ voice1、MTC '7' 自由文本直送同路径；**232_2 查证 = USART6 语音口，直送路径不变**）；音量字节按 §8 决定 9 执行层忽略（不再直通语音板）。语音板单帧文本上限 200B（`DEV_RS232_VOICE_MAX_TEXT`），超出截断——截断处可能切开 GBK 双字节字符（与 CQ voice1 同限制），待上位机确认最长文本口径。

## 3. 模块设计与接入点

- 目录/命名：`ProtocolParser_Anhui/`，前缀 `app_anhui_proto_`（`ah_` 前缀被 AH_MQTT 占用，doc/08 命名规则下用 `anhui`）；文件拆分与青海/贵州同构（proto / proto_parse / proto_cmd / proto_voice）。
- 注册五步：`RB_PROVIDE_WEAK`（RS485+RS232 同槽 weak 合并）→ `app_proto_acquire_buf` → `app_proto_register`（双通道各独立 mask）→ `app_proto_bind_channel`（CH_ID_RS485 + CH_ID_RS232）→ `app_proto_set_frame_queue`；`sw_app_initcall(anhui_proto_init)`。
- probe：**长度字段定界**（对齐治超 5.3 模式）——首字节 0x5A 快拒 → 命令字预筛（提前 FAKE 掉 5A 噪声流，避免大长度字段把链式探测拖死在 WAIT）→ 数据长算整帧 → 尾字节 0xA5 校验 → READY；屏号非 01 → SKIP 整帧消费。CRC 不校验（文档注明无检验）。PURE 契约（仅 rb_peek，仅 READY/SKIP 写 `*total_len`）。
- 队列：`ANHUI_PAYLOAD_MAX 261`（数据长 1B 上限 255 → 6+255）、`ANHUI_QUEUE_DEPTH 3`；`_Static_assert` ≤ RB 768。**队列体+控制块+任务帧缓冲为静态 SRAM（与青海/贵州/云南等协议模块一致，CQ 才是 CCMRAM 例外）**（§6、doc/06-04 记账）。
- 处理任务：`anhui_handle_task` 栈 256×4；帧缓冲 static（SRAM，不入栈）；parse 纯函数 → `anhui_execute_cmd` 查表分派。
- 应答：无（协议未定义）。
- 波特率：无协议改波特率命令，沿用 DIP1（9600/115200）全局选择。



## 4. 帧头冲突纪律

- 安徽帧头 `0x5A` 在 RS485/RS232 槽**唯一**：既有串口协议首字节为 `0x7B`（青海/山东/贵州/云南/四川MTC）/ `0x0A`（四川ETC）/ `0xFF`（四川治超/RLS），首字节互斥快拒成立，**无需 EIDE 目录排除**。
- IAP 的 `0x5A5A5A5A` 仅绑定 UDP（RJ45 槽），与串口槽不相交，无冲突。
- 安徽为 5A/A5 帧族，**非** `{` **帧族 → 不定义** `g_brace_proto_guard`；与青海/山东/贵州/云南/四川MTC 可同编共存（probe 注册序无关紧要，帧头互斥）。
