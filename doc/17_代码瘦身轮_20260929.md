## 4. 行为不变证据（方法）

1. **token 级「只删不改」校验**（`.analysis/cleanup_20260929/check_token_equivalence.py`）：
   逐文件比对改动前（备份 tar）与改动后源码的 token 流，断言「改动后 = 改动前的子序列」——
   任何新增/改写/重排都会失败；不可归属为纯删除的 4 个文件（Makefile / lwipopts.h /
   pl_task_guard.h / dev_display.c 的一行等价改写）在报告中逐条列明理由。
2. **机器码 A/B**：对核心业务函数做 `objdump -d` 前后对照（`mm_parse_frame`/`mm_apply_lamp`/
   `_mm_drive`、`frame_dispatch_task`、`init_task`、显示 `prepare`/`scan` 等），差异仅出现在
   被删调试语句处；结论与命令见报告 §5。
3. **注释精简零二进制影响**：注释精简后重建默认口径，段尺寸与 elf md5 与精简前一致（同口径
   重新编译的 md5 会因调试信息含行号而变化，故以**段尺寸 + 反汇编**为准，报告给出实测）。
4. **脚本**：`.analysis/22_1665/verify_all.sh --fast`、`.analysis/myanmar/mm_frame_sim.py`、
   `check_display_guards.py`、`check_eide_targets.py`、`.analysis/yn_ol/yn_ol_frame_sim.py`、
   `.analysis/heap/heap_ledger.py` 全部通过（逐项数字见报告 §6）。
