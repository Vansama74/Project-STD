## 1. 协议事实（帧格式 + 命令表）

**帧格式**（4 字节引导串 + 长度字段定界 + 尾部 `0x00`，**无校验**）：

| 偏移 | 长度 | 字段 | 取值/语义 |
|---|---|---|---|
| 0..3 | 4B | 引导串 | `54 43 4C 59`（ASCII "TCLY"） |
| 4..7 | 4B | 包序号 | 文档规定 `00 00 00 00`；**不读不校验**（与源固件一致） |
| 8..9 | 2B | 数据包长度 | **小端** = **整帧总长**（含引导串与结束符） |
| 10..11 | 2B | 保留位 | 文档规定 `00 00`；**不读不校验** |
| 12..15 | 4B | 命令字 | 4B 容器，**仅低字节有效**（文档「不足四个字节后面补 0x00」） |
| 16..N | 变长 | 基本数据包 | 含义随命令字 |
| N+1 | 1B | 结束符 | `0x00` |

帧总长 = 17 + 载荷字节数；命令处理收到的载荷长度 = 整帧长 − 17。
传输：**RS485 + RS232 + UDP 专用业务口 + UDP 10011 四通道**（UDP 两通道为 2026-09-14 用户裁决）：
- **专用业务口**（`CH_ID_UDP_GZOL`，2026-09-14 落地）：端口 = Sector1 `net_cfg.port`
  （与 TCP 业务口同号、不同协议栈），`0x40` 改端口即改此口 → 语义对齐源固件「设备自身 UDP 服务口」；
  出厂默认 **9528**；空/0 回退 9528，与 10011/CQ 业务口同号则跳过绑定（RTT 告警）；见 §13。
- **UDP 10011**（`CH_ID_UDP`，LDI 发现口 + IAP 同口，**保留**）：既有上位机仍可发 10011，
  应答走收包通道单播回源；源固件设备侧出厂端口 10028 与广播应答差异见 §11。
RJ45 槽 RB（1536B）由 IAP/LDI/CQ 同槽 weak 提供，本模块只 acquire、**不 provide**（不新增
第二份网口缓冲——`PROTO=ALL` SRAM 余量仅 448B）。
波特率 **9600 8N1** → **现场 DIP1 必须置 OFF（9600）**（`app_uart_baud` 为全局选择）。
文本编码 GBK（源固件字库为 GBK 点阵，渲染 `FONT_ENC_GBK` 直通）。

**命令表**：

| 命令字 | 文档语义 | 本实现行为 | 应答 |
|---|---|---|---|
| `0x10` | 获取故障信息 | 应答 2B 状态 `00 00`（无故障；STD 无故障采集点） | 0x10 帧（2B 载荷，共 19B） |
| `0x20` | 立即显示 | 解析 X/Y、屏宽/屏高（忽略）、字体名、字号、颜色、变长文本 → **先整屏清黑** → 按 (x,y) 渲染、按屏宽自动换行；**文本中字面 `\n`（0x5C 0x6E）解析为换行 0x0A**（2026-09-18 用户裁决；GBK 安全行走——GBK 尾字节 0x5C 不参与转义判定；`\r` 及其它转义不处理）；**字形框越出屏体几何由显示层整块丢弃**（前置条件「字号 ≤ 屏高」，见 §12） | 无（单向） |
| `0x30` | 清屏 | 整屏清黑 + 提交；**载荷长度不限**（源固件忽略载荷；文档帧例本身带 17B 参数块） | 无（单向） |
| `0x40` | 修改 IP（创迪扩展） | 写 Sector1 `net_cfg`（**写 `port`，不碰 `udp_port`**）→ 应答 `0x50` 帧 → `osDelay(100)` → `NVIC_SystemReset()`。**端口字段语义见 §13**（2026-09-14 用户裁决后：`port` 同时是 TCP 业务口与 GZ_OL 专用 UDP 业务口 `CH_ID_UDP_GZOL` 的监听口——**改端口对 GZ_OL 的 UDP 服务口生效**，重启后由 `_udp_gzol_read_port` 采纳）；**端口字段字节序 = 高字节在前 BE16**（2026-09-15 用户裁决，有意偏离源固件/协议文档：写 10028 发 `27 2C`，见 §13.5.1） | `0x50` 帧（14B 载荷，共 31B，**回显请求、非读回记录**） |
| `0x50` | 修改 IP 返回信息（文档） | **入站按源固件兼容处理为「搜索触发」**（与 `0x60` 同行为） | `0x70` 帧 |
| `0x60` | 搜索设备 | 读 Sector1 `net_cfg` 组 14B 载荷 | `0x70` 帧（**单播回源**） |
| `0x70` | 搜索设备返回信息 | 仅作为**出站**应答命令字；入站静默丢弃 | — |
| `0x80` | 文档未定义（创迪 2021.9.8 自加） | 三字节 RGB → 整屏纯色；副作用：**关闭光敏自动调光 + 亮度 8** | 无（单向） |
| 其他 | — | 静默丢弃（`GZ_OL_PARSE_ERR_CMD`；协议未定义错误应答） | — |

**`0x20` 载荷布局（17B 固定前缀 + 变长文本）**：

| 载荷偏移 | 长度 | 字段 | 处理 |
|---|---|---|---|
| 0..1 | 2B | X 坐标（小端，屏幕左上角为原点） | 采纳；≥屏宽时钳到 0 |
| 2..3 | 2B | Y 坐标（小端，像素） | 采纳；≥屏高时钳到 0 |
| 4..5 | 2B | 屏宽（小端，文档举例 192×80） | **读取后忽略**（以 `dev_display` 实际几何为准） |
| 6..7 | 2B | 屏高（小端） | **读取后忽略**（同上） |
| 8..11 | 4B | 字体名称（GBK 4B） | `宋体`→FONT_ST / `仿宋`→FONT_FS / `楷体`→FONT_KT / `黑体`→FONT_HT；未命中回退 FONT_ST |
| 12..13 | 2B | 字体大小（**两字节均为数值** 16/24/32） | 16/24/32 → FONT_16/24/32；**其余整帧丢弃**（源固件此处读未初始化变量属 UB，不复制缺陷）。**前置条件：字号 ≤ 屏高**（屏体几何），否则字形框越屏被显示层整块丢弃 → 清屏后屏幕无任何内容（§12） |
| 14..16 | 3B | 字体颜色（RGB） | `FF0000`→红 / `00FF00`→绿 / `0000FF`→**黄**（源固件口径）/ 其余→红 |
| 17.. | 变长 | 显示内容（GBK） | 文本（长度 = 载荷 − 17；可空）。**字面 `\n`（0x5C 0x6E）在执行层解析为换行 0x0A**（2026-09-18 用户裁决，GBK 安全行走：GBK 双字节字符尾字节为 0x5C 时不参与转义判定；`\r` 及其它转义不处理） |

**`0x70` 应答载荷（14B）**：`ip(4) + mask(4) + gw(4) + port(2 **高字节在前 BE16**)`。
`port` 字段报 Sector1 `net_cfg.port`（STD 统一"配置功能端口"口径，与 LDI 12H / IAP 0x01 一致；
2026-09-14 用户裁决后它同时是 **GZ_OL 专用 UDP 业务口**与 TCP 业务口的监听号）；
`udp_port`（CQ 专有）不参与（§8 Q5）。**字节序＝高字节在前**（2026-09-15 用户裁决，
`0x40` 请求与 `0x70` 应答同序；详见 §13.5.1）。

**应答帧构造**：与请求同帧族（引导串 + 序号 0 + 长度 + 保留 0 + 命令字 + 载荷 + `0x00`），
一律 `channel_send` 单播回源通道。

## 2. 与源固件／协议文档的不一致清单（逐条采纳）

| # | 项 | 文档 | 源固件 | 本实现（采纳） |
|---|---|---|---|---|
| 1 | 搜索命令字 | `0x60` | 实现在 `0x50` 上 | **`0x50` 与 `0x60` 都触发 `0x70` 应答**（覆盖文档版与固件版上位机，零成本、无副作用） |
| 2 | `0x10` 故障查询 | 应答 2B 状态位 | 空实现（不应答） | **应答 `00 00`**（文档「无此故障硬件的位补 0」→ 合规且诚实；源固件的静默会让上位机轮询超时，不复制缺陷） |
| 3 | `0x80` 全屏显示 | 文档无此命令 | 有（RGB 纯色 + 关自动调光 + 亮度 8） | **保留**（含三色之外的 RGB 不动屏幕行为） |
| 4 | 屏宽/屏高字段 | 举例 192×80 | 读取后忽略 | **忽略**（与安徽/四川等既有裁决一致：坐标上限以模组驱动实际屏幕尺寸为准） |
| 5 | 颜色 `00 00 FF` | 文档称"蓝" | 映射为 **yellow** | **复现源固件**（现场操作员看到的"蓝=黄"是既有事实；`display_color_t` 与源枚举同构，1:1 直映） |
| 6 | 端口字段字节序 | 未明示 | 写小端 / 读大端（自身不自洽，缺陷） | **改为高字节在前 BE16**（**2026-09-15 用户裁决，有意偏离协议文档与源固件**，对齐上位机现行帧：写 10028 发 `27 2C`，见 §13.5.1）；落 Sector1 由 STD 统一路径读回（无源固件「写读不自洽」缺陷）。**仅此一个字段**：帧长、`0x20` 的 X/Y/屏宽/屏高仍为小端 LE16 |
| 7 | 未知命令跳过长度 | — | 跳 `tempLen + 4`（越跳 4B，可吞下一帧帧头） | **不复制**：超长/非法帧由 probe 判定后整帧 SKIP 或 1 字节重同步，不越跳 |
| 8 | `tempLen` 未初始化 | — | 字号非 16/24/32 时使用未初始化变量 | **不复制**：字号非法 → `GZ_OL_PARSE_ERR_PARAM` 整帧丢弃 |
| 9 | 环形缓冲回绕缺陷 | — | `headPosition >= BUFFER_MAX` 时错误重置 `tailPosition` | **不复制**：帧由 STD 统一 RB/dispatch 管理 |
| 10 | 收到数据即开自动调光 | 未定义 | 有（`lightFLAG = true`） | **复现**：每帧处理前 `gz_ol_resume_auto_dim()`（解除 `0x80` 的挂起） |

## 3. 模块设计与接入点

| 文件 | 职责 |
|---|---|
| `app_gz_ol_proto.h` | 帧常量、命令枚举、解析结构体、对外 API |
| `app_gz_ol_proto_parse.h` / `app_gz_ol_proto_cmd.h` | 薄转发头（对齐四川治超风格） |
| `app_gz_ol_proto.c` | RB 提供（RS485/RS232 weak；**不 provide RJ45**）+ 注册（四通道四 mask）+ `gz_ol_probe_frame` + `gz_ol_proto_handle_task` + `sw_app_initcall` |
| `app_gz_ol_proto_parse.c` | `gz_ol_parse_frame()` 纯函数 |
| `app_gz_ol_proto_cmd.c` | 命令执行 + 应答组帧（`channel_send`） |
| `app_gz_ol_proto_default.c` | 上电默认画面注册（§7） |

- 任务：`gz_ol_handle_task`，栈 `256 * 4`（1KB，ucHeap），`osPriorityNormal`，帧缓冲 static；
- 队列：`GZ_OL_QUEUE_DEPTH = 3`，`GZ_OL_PAYLOAD_MAX = 256`（单槽 264B），四 mask 共用；
- 绑定（2026-09-14 起四通道）：`CH_ID_RS485` + `CH_ID_RS232` + `CH_ID_UDP`（10011，保留）
  + **`CH_ID_UDP_GZOL`（专用业务口，端口 = Sector1 `net_cfg.port`）**，每通道独立 mask
  （`s_gz_ol_mask` / `s_gz_ol_mask_rs232` / `s_gz_ol_mask_udp` / `s_gz_ol_mask_gzol`）；
  通道实例本身由 `app_boot.c` 的 `app_udp_gzol_start()` 启动（两口径无条件启动，与 CQ 实例一致）；
  **禁止** `CH_ID_RS232_1`（语音 TX 专用）；
- RB：`RB_PROVIDE_WEAK(rb_provide_rs485/rs232)` 与同槽协议 weak 合并；**RJ45 槽不 provide**
  （体由 IAP/LDI/CQ 提供，本模块 `app_proto_acquire_buf(RB_SLOT_RJ45, RB_SIZE_RJ45)` 取用；
  若某裁剪构建该槽无提供者则 acquire 得 nullptr → 静默跳过网口绑定，串口双通道不受影响）；
- 渲染互斥：`0x20`/`0x30`/`0x80` 的「清屏 + 渲染 + 提交」整段持 `app_scroll_render_lock`
  （与安徽动态滚动 `app_scroll` 渲染串行，消除同屏混合帧黑条；引擎未创建时空操作）。

**probe 判定链**（首字节快拒 + 引导串全匹配 + 长度/尾字节双重校验）：

```
① avail == 0                → FAKE   （禁止盲 WAIT 阻塞链式探测）
② peek[0] != 0x54           → FAKE
③ avail < 4                 → WAIT
④ peek[1..3] != 43 4C 59    → FAKE
⑤ avail < 10                → WAIT   （长度字段未到齐）
⑥ len < 17                  → FAKE   （结构下界 = 16 帧头 + 1 尾）
  len > 767（RB 上限）      → FAKE   （否则永久 WAIT 卡死同槽链式探测；三槽取保守下界
                                      `RB_SIZE_RS485-1`——RJ45 槽 1535 更宽不影响：结构
                                      合法帧 ≤256，超 256 走 ⑨ SKIP）
⑦ avail < len               → WAIT
⑧ peek[len-1] != 0x00       → FAKE   （尾字节定界）
⑨ len > 256                 → SKIP   （结构合法但超模块上限：整帧消费不入队）
⑩ 否则                       → READY，*total_len = len
```

**网口槽（RJ45）链式共存**：同槽 IAP(`0x5A5A5A5A`) / LDI(`0xFF 0xFF`) / CQ(`'{'` 或
`FF FF`+12B) 三个 probe 均对首字节 `0x54` 快拒 FAKE；本 probe 对 `0x5A`/`0xFF`/`0x7B`
首字节同样 FAKE → 双向不误吞（证据见 `.analysis/9k23881580/gz_ol_udp_binding_report.md` §2）。

## 4. 帧头冲突纪律（结论：**无冲突，无需互斥**）

| 槽 | 既有首字节 | 本协议首字节 |
|---|---|---|
| RS485 / RS232 | `0x0A` 四川ETC、`0x5A` 安徽、`0x7B` `{` 族（青海/山东/贵州/云南/四川MTC）、`0xFF` 四川治超 / RLS | `0x54` ✅ 唯一 |
| RJ45（UDP/TCP） | `0x5A5A5A5A` IAP、`0xFF 0xFF` LDI、`{` 或 `FF FF`+12B 重庆CQ | `0x54` ✅ 唯一（**2026-09-14 起已绑 `CH_ID_UDP` 10011 + `CH_ID_UDP_GZOL` 专用口**，两者同挂 RJ45 槽 RB；共槽证据见 §11 与报告 §2） |

- **双向首字节快拒成立**（宿主推演 §10 用例 5 已验证：四川治超 / RLS / `{`族 / 安徽 四个
  同槽协议与本协议互为 FAKE，各自认领自己的帧；网口槽 IAP/LDI/CQ 三个 probe 的首字节
  判别见 `.analysis/9k23881580/gz_ol_udp_binding_report.md` §2）；
- **反向证据（网口槽）**：IAP probe 首字节非 `0x5A` 即 FAKE（`app_iap.c:107-114`）；
  LDI probe 首字节非 `0xFF` 即 FAKE（`app_ldi.c:408-415`）；CQ probe 仅认 `'{'`（花括号
  深度扫描）与 `FF FF` 起始的 12B 精确匹配（重启/搜索两帧），其余首字节一律 FAKE
  （`app_cq_proto.c` `cq_probe_frame`）→ **不存在首字节可为 `0x54` 的 CQ 二进制帧**；
  AH_MQTT probe 虽对任意非空数据 READY，但其 `sw_app_initcall` 已注释未注册，且只 bind
  `CH_ID_MQTT`（不同逻辑通道），不影响 10011；
- **非 `{` 帧族 → 不定义 `g_brace_proto_guard`**，可与任何既有协议同编共存；
- **不需要 EIDE 目录互斥排除**（对比青海/山东/贵州/云南/四川MTC 的 `{` 族纪律）。

## 11. UDP 通道绑定与联调注意（2026-09-14 增绑 10011 + 专用业务口）

**绑定事实（2026-09-14 用户裁决后为四通道）**：`gz_ol_proto_init` 第三/第四次
`app_proto_register`（均挂 RJ45 槽 RB）+ `app_proto_bind_channel(s_gz_ol_mask_udp, CH_ID_UDP)`
与 `app_proto_bind_channel(s_gz_ol_mask_gzol, CH_ID_UDP_GZOL)`；probe 函数四通道共用（对
`ch` 参数不区分），四 mask 共用同一静态队列。RJ45 槽 RB（1536B）**由 IAP/LDI/CQ weak 提供，
本模块只 acquire 不 provide**；`PROTO=ALL` 与 `PROTO=CQ` 两口径该槽均有提供者
（`nm` 证据：`W rb_provide_rj45` + `b_rb_provide_rj45_buf.2` 在 CQ 口径 elf 中亦存在）。

**两条 UDP 通道并存**（端口语义与用法）：

| 通道 | 端口 | 用途与说明 |
|---|---|---|
| `CH_ID_UDP` | **10011 固定**（`LDI_DISCOVERY_PORT`，编译期常量） | LDI 发现口 + IAP 共用；**保留绑定**——既有上位机若仍发 10011，本协议照常应答（应答走收包通道单播回源）；与 CQ 搜索口同口互不干扰（首字节互斥） |
| `CH_ID_UDP_GZOL` | **Sector1 `net_cfg.port`**（出厂默认 **9528**，与 TCP 业务口同号不同协议栈） | **`0x40` 改端口的生效对象**（语义对齐源固件「设备自身 UDP 服务口」）；实例由 `app_udp.c` 的 `udp_gzol_task` 承载（镜像 CQ 实例：常驻 netconn + 独立 connect 任务 + 断链重建 + `SOF_BROADCAST` 可收广播帧） |

`_udp_gzol_read_port()` 的端口来源与回退（每轮重建前重读，`0x40` 重启后生效）：
`net_cfg.port` 合法（1~65535）→ 采纳；**记录无效 / port=0 → 回退 9528 并 RTT 告警**
（不静默绑定 0）；**与 10011 或 CQ 业务口同号 → 跳过本实例绑定并 RTT 告警**（同口二次
bind 必 `ERR_USE`；10011 场景 GZ_OL 仍由 `CH_ID_UDP` 承载，功能不受损）。

**与源固件的端口/应答语义差异（联调必读）**：

| 项 | 源固件 9K23881580 | 本实现（STD） |
|---|---|---|
| 设备侧出厂 UDP 口 | **10028** | **9528**（= `net_cfg.port` 出厂默认，两口径统一）；`0x40` 可改 |
| 上位机目标端口 | 10028 | **9528 或 `0x40` 设定的新端口**（10011 仍可应答，兼容旧配置） |
| 搜索应答目的地址 | **广播**（`255.255.255.255`） | **单播回源**（`channel_send` → `udp_ch_send` 按通道缓存的 `src_ip`/`src_port` 发回） |
| 搜索触发命令字 | `0x50`（实现在 0x50 上） | `0x50` 与 `0x60` 均触发（§2 #1） |
| 应答帧内容 | 同帧族 | 同帧族（14B 载荷：ip4+mask4+gw4+port2 **高字节在前 BE16**） |

→ 上位机把目标端口设为**设备 `net_cfg.port`（默认 9528）**即可；按源固件出厂值 10028
发帧设备收不到（改端口用 `0x40`，或把上位机目标改成 9528）。搜索应答为单播回源，上位机
若按源固件只监听广播应答需改为监听本机源端口（或后续按需改成广播，见下）。

⚠️ **端口字段字节序（修订：2026-09-15 用户裁决）**：`0x40` 的端口字段**改为高字节在前（BE16）**，
**不参考协议文档**——写 10028 发 **`27 2C`**（上位机现行帧写法，改后即生效）；发 `2C 27`
会被解析为 **11303**（与改前互换）。`0x50`/`0x70` 应答载荷 `[12..13]` 与请求同序（BE16）。
**历史口径（2026-09-14~09-15 改前）**：本字段曾按小端 LE16 解析（写 10028 须发 `2C 27`），
当时现场「向 10028 无响应」据此定案为上位机大端编码（E 类）——该结论已被本次裁决取代，
沿革见 §13.5.1 与 §14 修订记录。

**应答路径核对（结论：可用）**：`channel_send(ch, ...)` → `app_channel_get(ch->ch_id) == ch`
回验（`s_udp_ch` / `s_udp_gzol_ch` 均为文件级单实例，`app_udp.c`）→ 各自实例的 `_ch_send`
用本实例缓存的 `src_ip[4]` + `src_port` 重建目的地址 `netconn_sendto`。
**每实例独立 src 快照**：从 10011 收到的帧回 10011 源端、从专用口收到的帧回专用口源端
（`frame_msg_t.ch` 携带收包通道指针）——两条通道并存不会串台。字节序已核对：接收侧
`udp.c:234` `src = lwip_ntohs(udphdr->src)`（主机序）→ `netbuf_fromport` 主机序；发送侧
`netconn_sendto` → `udp_sendto` → `udp.c:786` `lwip_htons(dst_port)`（主机序入参）→ 语义自洽。
**已知限制（与 IAP/LDI 同源）**：`src_ip`/`src_port` 是**通道级单例快照**，帧排队期间若另一
客户端恰好发到同一通道会覆盖快照 → 应答可能发往最后发包者；本协议应答均为「一问一答/
上位机停等」（0x10/0x50/0x60/0x70），单客户端联调不受影响，多客户端并发时不保证逐帧回源。

**可选后续（本轮不做）**：

1. **搜索应答改广播**：如需复现源固件广播应答，可复用 `app_udp_broadcast(data,len)`
   （10011 口广播，复用常驻 conn、不占 netconn 池）——须与用户确认上位机是否依赖广播。
2. **专用口广播应答**：如需从专用口广播，可在 `app_udp.c` 为 `CH_ID_UDP_GZOL` 增设

3. **`0x40` 端口字段语义**：2026-09-14 实机判定「语义不匹配」→ **已由用户裁决落地**
   （专用 UDP 业务口），见 §13。

## 12. `0x20` 字号与屏体几何（2026-09-14 实机复盘 → 同日晚裁决改为「可见部分裁剪绘制」）

**现场现象**：实机 `0x20` 发 16 点阵正常显示，发 24/32 点阵屏幕上**什么都没有**（非花屏、非乱码）。
**定位结论**：帧解析、字库、地址公式全部正常；根因是**当时板上镜像的屏体几何为 32×16**（16:02 烧录的是 EIDE Debug 构建，链接 `dev_display_22_1703`，且该文件处于 1×1 实验态），24/32 字形框（24×24 / 32×32）超出屏高 16px 后被显示层**整块丢弃**。完整证据链（含上位机 DLL 反汇编、字库文件解码、elf 实例字段实测）见 `.analysis/9k23881580/gz_ol_font_size_bugfix.md`。

### 12.1 字号判据（与源固件逐字节一致）

- 字号字段 = 载荷 12..13 两字节，**必须两字节相等**且取值 ∈ {16,24,32} → `FONT_16/FONT_24/FONT_32`；
  其余 → `GZ_OL_PARSE_ERR_PARAM` **整帧丢弃**（源固件此处沿用上一帧字号 = UB，不复制该缺陷）。
- 上位机（随源项目交付的 `2022_贵州贵黔高速_治超屏测试软件_黔通智联`：`CD_GuiZhou_QBB.dll` 导出 `IFB_Display`）实际发送：**`10 10` / `18 18` / `20 20`**，X=0、Y=0，屏宽=192、屏高=80（后两者本实现忽略），颜色 `FF0000`/`00FF00`，文本 GBK。
  → **三种字号的帧都能被正确解析**，不存在「24/32 被拒」的情形。

### 12.2 字库前提（本协议支持的物理条件）

- 本实现按 `app_render` 当前生效的字库芯片配置取 `(字号, 编码, 字型)` 三元组；本协议要求三档字号 × 四字型（宋/仿/楷/黑）齐备，与源固件字库 `贵州P10双色治超屏字库`（8MB、非连续布局、GB2312 94 列序）**完全对齐**——区块地址已与源固件 `FUNC/func.h` 宏 + `FUNC/func.c` 读取公式逐字节对拍一致（24GBK 宋体 1164160 起、72B/字；32GBK 宋体 3741952 起、128B/字）。
- 字形字节数：ASCII `字号 × ((字号/2+7)/8)`、GBK `字号 × ((字号+7)/8)` → 16/24/32 GBK = **32/72/128B**（与源固件 `W25QXX_Read(font_buf, readaddr, 72/128)` 一致）。
- 字库配置由 **DIP2** 选择（`app_render.c:351-357` `_dip_font_select`）：现场须保证所选配置与板上字库实际布局一致（**16 点阵能正常显示即已间接验证**）。若真出现 24/32 区块缺失：`_find_region` 回退首项会画出**错误尺寸字形**、字库未编程读回 `0xFF` 呈**实心块**——**都不是"空白"**，可据此区分。

### 12.3 屏体几何（2026-09-14 晚修订：字形按屏幕交集裁剪绘制）

- 执行层传参：`w = 屏宽 − x`、`h = 屏高 − y`（由 `dev_display_get()` 实际几何推导，**从不写死 16**）。
- **历史机理（修复前，本轮事故的直接原因，保留备查）**：字符渲染逐字形调用
  `dev_display_draw_bitmap(cur_x, cur_y, 字号, 字号, …)`；该函数当时对「字形框越屏」是
  **整块早退丢弃**（`Device/Display/dev_display.c:229-233` 旧实现；与同文件
  `dev_display_fill` 的截断填充语义不同），**不是部分绘制** → 配合 `0x20` 先整屏清黑，
  「字号 > 屏高」表现为**屏幕全黑无内容**。
- **现行行为（2026-09-14 用户裁决，见 §12.6）**：字号**不再受屏高限制**——
  ① 渲染层只对「行首已完全越出渲染区域」（`cur_y >= h`）的行终止，行框下缘越屏但行首仍在
  区域内 → 保留绘制；② 显示层 `dev_display_draw_bitmap` 越界由整块丢弃改为**按屏幕交集
  逐像素裁剪绘制**（MSB-first 位图，裁剪只发生在右/下边界，位序不错位）。
  因此「字号 > 可用高度」时字形露出**可见的上部**：

| 屏体几何 | 16pt | 24pt | 32pt |
|---|---|---|---|
| 224×64（1-263 7×2、22-1703 7×4；与源固件同几何） | ✅ 完整 | ✅ 完整（末行下缘越屏时改为画可见部分，见 §12.6） | ✅ 完整 |
| 32×16（22-1703 1×1 实验态 = 单块 P10 模组） | ✅ 完整（16 ≤ 16 恰好通过） | ✅ 上部 16 行（字形 24 行） | ✅ 上部 16 行（字形 32 行） |

- 屏**宽**不足时仍是**换行**（`word_wrap=true`）；屏**高**不足由「整字形丢弃」改为「裁剪绘制」。

### 12.4 联调诊断（`APP_DIAG_BANNER` 总开关 → `GZ_OL_RTT_DIAG` 跟随，默认开）

`app_gz_ol_proto_cmd.c` 的 `_gz_ol_exec_display()` 对每帧 `0x20` 经 RTT 通道 0 打印（2026-09-14 复测轮扩写，**当前代码实态**）：

```
[gz_ol] 0x20 plen=19 payload[0..15]=00 00 00 00 c0 00 50 00 cb ce cc e5 18 18 ff 00
[gz_ol] 0x20 x=0 y=0 size=24 type=0 color=1 text_len=2 -> render x=0 y=0 w=32 h=16 wrap=1 enc=GBK
[gz_ol] 0x20 size-map field=24/24 -> FONT_24 glyph_box=24x24
[gz_ol] 0x20 screen=32x16 code=2200001703 glyph_visible=24x16 of 24x24 *** glyph CLIPPED by screen edge (draw_bitmap intersection) ***
[gz_ol] 0x20 pixel_map before render: nonblack=0
[gz_ol] font-probe chip=W25Q64 cap=8192 enc=GBK type=0 ch=cb,ce
[gz_ol]   size=16 addr=0x000000 inCAP=1 rd=0 nz=41/32 head=...
[gz_ol]   size=24 addr=0x1164a0 inCAP=1 rd=0 nz=33/72 head=...
[gz_ol]   size=32 addr=0x391a80 inCAP=1 rd=0 nz=78/128 head=...
[gz_ol]   alt-layout(MX25L256) addr 16=0x... 24=0x... 32=0x... (arith only)
[gz_ol] 0x20 post-render: nonblack=384 first_color=1 commits=17
```

- 判读：`glyph_visible` = 字形框与屏幕的交集尺寸（**裁剪后可见**），不再有「`size_fits`」字样；
  末段 `*** glyph CLIPPED ... ***` 表示字形被屏幕边界裁剪（仍是「有内容」）。
- 字库三档实读（`font-probe` 段，**决定性证据**）：逐字号给 `addr`（Flash 绝对地址）/ `inCAP`
  （地址是否在芯片容量内）/ `rd`（`dev_storage_read` 返回码，0 = 成功）/ `nz/total`
  （读回的非零字节数 / 应读字节数）/ `head`（前 8 字节）；末行是**另一套芯片布局的纯算术地址**
  （不读 Flash），用于判「激活布局是否选错（DIP2 / 字库芯片型号）」。
- `post-render: nonblack` = 渲染后 `pixel_map` 非黑像素数：`>0` = **渲染确已落屏**（屏幕若仍无内容 →
  问题在扫描/屏体/接线）；`=0` → 渲染/裁剪/字库侧（结合 `font probe` 判定）。
- **一键移除**：`make APP_DIAG=0`（或把 `Application/Inc/app_diag.h` 的 `APP_DIAG_BANNER` 改 0）；
  单独关 GZ_OL 逐帧证据可把 `GZ_OL_RTT_DIAG` 置 0（`app_gz_ol_proto_cmd.c:118-120`，默认跟随总开关）。

### 12.8 一条定案诊断（开机一行自报，零新增代码）

既有的 `APP_DIAG_BANNER` 设施（`Application/Inc/app_diag.h`，默认 1；`make APP_DIAG=0` 一键关）
在 `app_boot.c` `init_task` 的 `app_net_boot_apply()` **之后**、通道全部启动**之后**各打一组 RTT，
把「我是谁 / 屏体几何 / 网络配置 / 各 UDP 服务口绑定结果」变成可直接读出的事实：

```
[diag] fw=0000000000 built=<日期> <时间> tree=<8位树哈希>
[diag] build proto=ALL disp=1_263 config=Debug toolchain=gcc
[diag] display screen=224x64 code=1000000263 scan_lines=8 chans=4
[diag] driver linked? 1_263=1 22_1703=0 (exactly one expected)
[diag] netcfg VALID ip=192.168.114.200 mask=255.255.255.0 gw=192.168.114.1 port=9528 udp_port=20103
[diag] ports t0 udp10011=10011 tcp_biz=9528 cq_udp=20103 gzol_cached=9528 (expect gzol=9528 = net_cfg.port; ...)
[diag] chan udp10011=UP port=10011 | cq_udp=UP port=20103
[diag] chan gzol=UP port=9528 bind=OK | tcp_srv=UP port=9528
[diag] netcfg readback port=9528 udp_port=20103 (source of truth)
```

- **一行定案**：**没有 `[diag]` 行 ⟹ 板上不是这份代码**（旧镜像）→ 全部现象由镜像陈旧解释。
- `bind=OK / SKIPPED(port busy with 10011/CQ) / FALLBACK(9528, net_cfg.port invalid) / FAIL(...)`
  四态即端口链路的全部可能结论（`app_udp.c` `s_udp_gzol_bind_sta`）。
- **`gzol_cached` 不是实际服务口**（它是任务启动前的静态初值 9528）；实际服务口只看 post-boot 行
  `chan gzol=… port=… bind=…`，`expect gzol=` 是记录真源 `net_cfg.port`。
- **启动即回滚的自证行**（复测轮 ② 新增，`app_net_boot.c` `accept_write` 分支）：
  `[diag] netcfg INVALID at boot (record ok but net invalid): ip=… port=… -> accept_write defaults`
  或 `… (magic/CRC bad) -> accept_write defaults`——出现即表示**记录被判非法、IP 与 port 一起被默认值覆盖**
  （「0x40 改端口看似没生效」的成因 B：例如帧里 IP 写成 `0.0.0.0`）。
- 增量（默认口径 A/B 实测，复测轮 ②）：**Flash +5616B**（text +2640 / rodata +2976）、**RAM +0B**
  （data/bss/ccmram 零变化）。唯一行为差异：开机默认画面延后 2.5s（`osDelay(2500)`，通道与协议不受影响）。
  诊断关闭时（`make APP_DIAG=0`）段尺寸与加写诊断前**逐字节同尺寸**（`--gc-sections` 丢弃）。
- 完整判读表与现场清单见 `.analysis/9k23881580/field_triage_2432_and_port.md` §③/§④；
  「改端口不生效」状态判别契约（**A~E，E 类＝2026-09-14 实机定案的上位机端口字段大端编码；

### 13.2 历史机理（保留，供现场回溯）

- **落盘是原子的**：`app_board_net_cfg_update` 把 `ip/mask/gw/port/udp_port` 写进同一 `net_cfg`
  后**一次擦除 + 一次 72B 写**（`app_board_net_cfg.c:155-156`、`:166-170`）。
  **IP 生效 ⇒ 同一笔写成功 ⇒ 端口字段确已落盘**（擦/写失败会整条回滚；同值跳过要求全 `net_cfg` 相同）。
- **裁决前**：IP 是 netif 全局属性（所有 socket 一起迁），端口只被 `app_tcp_server_set_port`
  消费（TCP 监听口 9528→X），GZ_OL 服务口恒 10011 → 上位机改端口后设备不在新口应答，
  现象即「端口不生效」；另有跨协议副作用（本协议改端口会迁移 LDI/IAP 的 TCP 口）。
- **裁决后**：专用 UDP 实例随 `net_cfg.port` 迁移 → 端口生效；TCP 业务口同号迁移仍保留
  （`net_cfg.port` 本就是 LDI/IAP 生态字段，两消费者同源同值，不再是「隐藏副作用」而是
  协议与 STD 口径的并集——上位机改端口会同时改 TCP 口，属**已知且已文档化**的跨协议影响）。

### 13.3 as-built：专用实例（`app_udp.c` / `app_boot.c` / `app_gz_ol_proto.c`）

- **实例**：`udp_gzol_task`（常驻 netconn + bind + 断链重建）+ `udp_gzol_connect_task`
  （recv → `app_channel_dispatch`），完全镜像 CQ 业务口实例（`_udp_cq_*`）；
  通道模板 `CH_ID_UDP_GZOL`；`SOF_BROADCAST` 已置（可收广播帧，`IP_SOF_BROADCAST_RECV=1` 前提）。
- **端口来源**：`_udp_gzol_read_port()` 读 Sector1 `net_cfg.port`（合法 1~65535 → 采纳；
  每轮重建前重读 → `0x40` 重启后生效）。
- **端口字段字节序（2026-09-15 用户裁决）**：`0x40` 解析 = `_gz_ol_be16(&payload[12])`
  （`app_gz_ol_proto_parse.c`，高字节在前）；`0x50` 回显与 `0x70` 读记录回读 = `[port >> 8,
  port & 0xFF]`（`app_gz_ol_proto_cmd.c` `_gz_ol_net_payload` / `_gz_ol_exec_set_ip`）——
  收发同序，回读值与落库值一致。**仅此字段**，其余 16 位字段（帧长、X/Y/屏宽/屏高）保持 LE16。
- **回退策略**：记录无效 / `port == 0` → 回退 **9528**（`net_cfg.port` 两口径出厂默认）+
  RTT 告警（**不静默绑定 0**）；正常路径由 `app_net_boot_apply` 先行修复记录，此分支为防御。
- **同口冲突**：`port == 10011`（发现口）或 `== CQ 业务口` → **跳过本实例绑定** + RTT 告警
  （同口二次 bind 必 `ERR_USE`；10011 场景 GZ_OL 仍由 `CH_ID_UDP` 承载，功能不受损）。
  告警闩锁：同一异常端口值只打印一次，不周期性刷屏。
- **启动时序**：`app_boot.c` 在 `app_net_boot_apply()` 之后调用 `app_udp_gzol_start()`
  （与 `app_udp_cq_start()` 相邻），端口在任务 bind 前已按 Sector1 应用。
- **枚举扩容**：`CH_ID_MAX 8→9`（`ch_proto_map[]`/`channels[]` 各 +4B bss，`app_dispatch.c`
  的两处 `ch_id < CH_ID_MAX` 越界守卫自动覆盖新值）。
- **LwIP 池**：常驻 netconn 5（10011 + CQ + 专用口 + TCP listener + TCP client），
  叠加已连接客户端与广播回退临时 conn 峰值 8 = `MEMP_NUM_NETCONN(8)`，**维持 8 不扩**
  （`MEMP_NUM_UDP_PCB` 常驻 3/8）；核算详见交付报告 §4。
- **内存**：`PROTO=ALL` `DISP=1_263` 静态增量 text +752 / rodata +296 / data +8 / bss +40，
  ccmram +0，SRAM 余量 496→**448B**；ucHeap 另 +2 任务（2×1KB 栈）。

### 13.4 现场复测（判定矩阵）

1. 发 `0x40`：`54 43 4C 59 00 00 00 00 1F 00 00 00 40 00 00 00 C0 A8 01 64 FF FF FF 00 C0 A8 01 01 27 2C 00`
   （IP=192.168.1.100，端口=10028=0x272C **高字节在前**，2026-09-15 用户裁决）；设备约 100ms 后复位。
2. 重启后把上位机目标设为 **新 IP + 10028**，发 `0x60` 搜索 → 0x70 应答载荷 `[12..13]` 应为 `27 2C`
   （注：`0x50` 修改应答是**回显请求**，**不能**作为落盘证据；0x70 是读记录回显）。
3. **端口生效判据**：UDP 发 **新 IP:10028** → **有应答**（= 专用口已按新端口服务）；发
   **192.168.1.100:10011** → 仍应应答（兼容通道保留）；TCP 连 10028 亦通（同号不同协议栈）。
4. 若第 2 步回的是**旧端口**，才需回查写入路径（当前实现无此现象）。

| 现象 | 结论 |
|---|---|
| 0x70 回新端口 + UDP 新端口有应答 + 10011 有应答 | ✅ 裁决落地生效（本实现目标态） |
| 0x70 回新端口 + UDP 新端口**无**应答 | 专用实例未绑定（查 RTT：`net_cfg.port invalid` / `busy ... skip bind` 告警） |
| 0x70 回旧端口 | 写入/落盘失败 → 抓 RTT + 查 Sector1 记录 |

**判定必须用「新端口实发」（2026-09-14 复测轮补）**：`0x40` 的 `0x50` 应答是**回显**（`ack=0x50 echo (NOT evidence)`，
`app_gz_ol_proto_cmd.c:432`）；核验顺序固定为
① 重启后读 **`[diag] netcfg readback port=`**（落盘真源）；
② **`[diag] chan gzol=... bind=`**（绑定实况，四态见 §12.8）；
③ 向**新端口**发 `0x60` ≈ 期望 `0x70`（14B 载荷 `port` 字段**高字节在前 BE16** = 新值，2026-09-15 裁决）、发 `0x10` ≈ 期望 2B `00 00`。
两个**设计分支**会表现为「改了没生效」而不是缺陷：**端口值 = 10011 或 20103 → `SKIPPED`（不绑，GZ_OL 仍由 10011 承载）**；
**端口值非法/0 → `FALLBACK(9528)`**。复测取值请避开 10011/20103 与改前同值。
注意 **10011 有应答不能否定「新端口已生效」**（兼容口保留，两通道并存）。

写 10028 发 `27 2C`；发 `2C 27` 会被解析为 11303**（两串字节恰好互为倒序）。`0x50`/`0x70`
应答载荷 `[12..13]` 同为 BE16（`0x70` 回记录值，可用于自检上位机编码）。

**发送帧示例（设备 IP 192.168.114.201、目标端口 10028，31B，可直接复制）**：

```
54 43 4C 59 00 00 00 00 1F 00 00 00 40 00 00 00 C0 A8 72 C9 FF FF FF 00 C0 A8 72 01 27 2C 00
```

（IP `C0 A8 72 C9`=192.168.114.201 / 掩码 `FF FF FF 00` / 网关 `C0 A8 72 01` /
端口 `27 2C`=10028 **高字节在前**；发往设备当时服务口，重启后设备改在 10028 服务。）

**判别签名（现行）**：`[gz_ol] 0x40 port field payload[12..13]=27 2C -> 10028 (BE16)`
→ `write ret=0 / readback port=10028` → `[diag] netcfg VALID … port=10028` →
`[diag] chan gzol=UP port=10028 bind=OK`。（历史签名 `…=27 2C -> 11303 (LE16)` 对应 2026-09-15
之前的旧镜像，判读时以 `(LE16)/(BE16)` 标注区分。）
宿主推演已同步：`gz_ol_frame_sim.py` **共 105 用例通过 / 失败 0**——含「`27 2C` → 10028 生效」、
「`2C 27` → 11303 交换值」、「`0x40` → `0x70` 端口回读一致性」回归。
