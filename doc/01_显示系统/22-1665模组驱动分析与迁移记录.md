### 0.2 数据流

```
渲染/协议 → dev_display_set_pixel/fill/draw_bitmap → pixel_map[W×H]（1B/像素，颜色索引 0..7）
   ↓ prepare（脏矩形只用于判「有无变化」；每次提交整帧重算）
frame_state[128×M]：**按组分段** `state[组 g × CLOCKS + 时钟位 p]`，每字节 **bit j = 组内第 j 条线**的电平
   · 红线段取像素 R 位（bit0）、绿线段取 G 位（bit1）；黄 = 两条都亮
   · 蓝分量策略已固化（蓝/紫/青/白 让红绿都亮，见 §0.4；第二十九轮删除 `_22_1665_BLUE_AS_LIT` 开关）
   · 组 g（= 模块列 g）载模块 m = g×ROWS + local（local = 0..ROWS-1）；组内块 b 装
     链段 [(ROWS-1-b)×128, (ROWS-1-b+1)×128)（默认 flip=0：链上最后移入的 128 位停在链首 = 行尾块）；
     `MODULE_ROWS = 1` 时每组仅一块 ⇒ 整块收满 128 位（**不再丢首 128 位**）
   · 状态字节**一线一位**（恒 4 位 / 16 状态）——这是链段数能超过 8 的前提（旧口径一链一位）
   ↓ scan（每帧一次，静态 line 恒 0）
逐时钟位 p、逐组 g 查合并写表 `_22_1665_bsrr_tab[组][端口槽][st]` → 按端口写 BSRR
        （每组 2 次：组 0 = PG+PB、组 1 = PB+PE；1×2 共 4 次/时钟）→ 4×NOP → CLK 脉冲
帧末由基类在 OE 消隐窗口内打 LAT；↓ set_row(0)
静态单扫：`pl_hub75_Decoder_set_row(0)`（数据线都在 RGB 数据脚上，A/B/C/D 不做数据线）
```

### 0.3 链与落点规则

**数据线表** = `_22_1665_lines[5][4]`（驱动「物理数据线」一节）：**组 × 4 行**（组 g = 通道对 `2g/2g+1` 的
R/G 脚），`{线名, 数据脚（g_hub75_pin_* 表项）, 颜色角色, 半屏}`——**前 `MODULE_COLS` 组在用**；
每行的 role/half 模式恒 `{RED,0}/{GREEN,0}/{RED,1}/{GREEN,1}`（与组号、模块数无关）；换接线才改。
**链段 = 模块 × 线**（共 `4 × M` 段），行号 `m×4 + j`；**区域 (x0,y0,w,h) 不入表**，
由模块序号（行主序）+ 线序号推导：

```
模块 m 的栅格位 (mx, my) = (m % MODULE_ROWS, m / MODULE_ROWS)
链段 (m, j)：区域 = (mx·MODULE_PIXEL_ROW, my·MODULE_PIXEL_COL + lines[j].half·HALF_COLS,
                    MODULE_PIXEL_ROW, HALF_COLS)
现行 1×1：链段 0/1 = (0,0,16,8)，链段 2/3 = (0,8,16,8)
```

每个模块列（= 一个 HUB 口）各占一组 4 根数据脚（组 g = 通道对 2g/2g+1）；**各组并行**、共享

**落点规则**（第十二轮由现场两条观测反解、逐位确认，现为唯一模型，无旗标/无逃生口）：

```
段内局部位 p'（0..127）：片 c = p' / 16、片内级序 i = p' % 16
块栅格：blk_cols = 区域宽/4（16×8 区域 → 4 列 × 2 行）
       bc = (blk_cols - 1) - (c % blk_cols)      ← 块列反向
       br = c / blk_cols
块内： dx = 3 - (i % 4)、dy = ((i / 4) + 2) % 4   ← 反解出的唯一解
屏面： (X, Y) = (x0 + 4*bc + dx, y0 + 4*br + dy) → pixel_map 偏移 = Y*SCREEN_ROWS + X
```

**合法性与边界：无编译期防御**（第三十四轮用户裁决删除全部 **17 条 `_Static_assert`**）。
下列约束降级为**源码注释里的契约 + 本文档**（驱动文件头「物理约束（契约，非编译期守卫）」一行）：

- 模块数 ≥1 且 ≤255（基类字段是 `uint8_t`）；
- 单模块宽为 4 的倍数、高为偶数、半屏高 ≥4 且为 4 的倍数、
  **单模块单链段区域恰 8 块 = 128 位（单模块须 256 像素：16×16 / 32×8 …）**；
- 每组线数固定 4、链数 = 4 × 模块数、状态数 ≤256、像素数/帧位数 ≤65535；
- **通道数 `2 × MODULE_COLS ≤ HUB75_CHANNEL_MAX = 10`（⇒ `MODULE_COLS ≤ 5`）** —— 最危险的一条：
  `_22_1665_lines` 只预声明 `HUB75_CHANNEL_MAX / 2 = 5` 组，`MODULE_COLS ≥ 6` 时
  `prepare` / `init` 会**越界读**该表（`-O3` 下 gcc 报 `-Waggressive-loop-optimizations`（UB），
  `-fsyntax-only` 下**静默**）；
- **状态数组 = 组数 × 每帧时钟数**；
- **本模组数组 ≤ 整片 CCMRAM 区域 64KB**（芯片事实 / 链接脚本 `CCMRAM (xrw) LENGTH = 64K`）。

**越界与错口径的后果（第三十四轮实测，写死为脚本期望）**：非法几何**不再编译报错** ——
`MODULE_ROWS=0` 编过但有 `-Wdiv-by-zero`（落点表除以 0 模块/行）；`MODULE_COLS=6` 编过
（`-O3` 有 UB 告警）；单模块 24×16 / 16×32 / `PIXEL_COL=30`、`MODULE_COLS=0` **零告警编过
= 静默错口径**；`MODULE_ROWS=47`（本模组 CCM 66432B > 64KB）**对象零告警、链接期**由链接器拦下

### 0.11 双 HUB 口现场现象判定（**第二十六轮**，2026-09-17 傍晚）

那次只有 1 个字且只在上半屏，故单块看默认画面全黑）。

**机器级帧归属**（宿主直跑驱动产物）：每帧 256 时钟；扫描 p 递减 ⇒ 先移入 `state[255]`、

## 1. 硬件与器件口径

### 1.1 MBI5034B

- 特性：**16 通道恒流下沉**（数据 1 = 点亮）+ **16 位移位寄存器** + 输出栓锁；SDO→SDI 级联。
- 信号与做法：SDI（各链自己的数据脚）→ `pl_hub75_bsrr_flush` 按端口合并写；CLK = `pl_hub75_clock_pulse()`
  （CLK=1 → 2×NOP → CLK=0，**上升沿采样**）；LE/LAT 由基类在帧末 OE 消隐窗口内打一次；OE 低有效 + TIM4 PWM 8 档。
- **级联方向**：先移入的位最终停在链尾 ⇒ 链上 128 位 = 帧内最后移入的 128 位；落点表把
  「链位 p → 屏面 (X,Y)」映射一次算好（§0.3），scan 只查表。
- **两处族内细节**（如需精修再动）：① 片内级序与输出序号的关系已由现场反解确定（体现在
  `dy = (i/4 + 2) % 4` 的偏移里），无需再猜；② LE 多脉冲可调输出电流增益，本驱动只打单脉冲（默认增益）。

### 1.2 静态扫描与基类兼容

| 项 | 扫描类模组（1/4、1/8 扫） | 本模组（静态） |
|---|---|---|
| 行址线 A/B/C/D | 逐行选通 | **不用**（可被板卡当数据线用；本模组实测 A/B/C/D 与 B1/B2 均无链） |
| `scan_lines` | 4 / 8 | **1** |
| 一次 `scan()` | 一个扫描行的位流 | **整帧 128 个时钟位** |
| 换帧 | scan → OE 消隐 → set_row → LAT | scan → OE 消隐 → set_row（恒 0）→ LAT |

基类 `dev_display.c` 的 scan_task 对静态扫描零改动可用：`scan_line` 恒 0、OE/LAT 原子窗口照常；
`_22_1665_set_row()` 只在「地址脚未被选作数据脚」时写 0（见 §0.2）。

### 1.3 时序与电平风险（现场排障参考）

- 数据脚与 CLK 不在同一 GPIO 端口 → 数据先于时钟的建立量由 `_22_1665_BIT_MARGIN()`（4×NOP
  ≈24ns @168MHz）保证；现场判「随机散点 / 随时间变化」时可把该宏加到 8/16 个 NOP
  （帧时长 25~35µs → 60~80µs，TIM3 500µs 周期余量仍 6 倍以上）。
- **LAT 脉宽偏紧**（≈20~30ns，MBI 系列最小值典型 20ns）——若出现「间歇性乱」，优先示波器看 LAT。
- **3.3V→5V 电平**：MBI5034B 若 VDD=5V，VIH≈3.5V > MCU 3.3V，是「随机错位/乱码」的常见硬件原因。

## 2. 位流与落点模型

### 2.1 并行喂（多链的硬约束）

> 第二十七轮补充：模型 B 下「并行」体现在**组间并行**（各组同时收时钟、各写自己的 4 根脚）；
> 组内横向模块仍是同线级联（串行喂 128 位/块）。模型 A 下则是单组串行喂全部链段。

一帧时钟位：**模型 B = `128 × MODULE_ROWS`**（每组并行、组内横向模块串行）；
**模型 A = `128 × M`**（M = 模块总数）。每个时钟位把「该时钟所属模块的 4 条数据线各自的第 p' 位
**同时**」写到本组的 4 个数据脚（各组共享 CLK/LAT）。**必须并行喂，不能分时**——分时会让其余线的
移位寄存器吃进垃圾。合并成一个「状态字节」后：
- 模型 B：每时钟位**逐组**查表 → 每组按 GPIO 端口合并写（1×2 = 4 次：组 0 的 G/B + 组 1 的 B/E）；
- 模型 A：每时钟位按端口合并写 ≤3 次（本板 2 次）。
**模块靠链上位置拿到自己那 128 位**（§0.3）：模型 B = 组内块号（`MODULE_ROWS=1` 时每块整收 128 位）；
模型 A = 同线级联的先后顺序。

## 4. scan 热路径与 CPU 估算（`-Og` 反汇编实测）

默认口径（多链、2 端口：R1/G1/R2 在 GPIOG、G2 在 GPIOB）每时钟位 ≈ **33 条指令**：

```
取状态字节（ldrb）→ 表基址 + 状态×8 → 端口/值各一取 → BSRR 写（第 1 端口）
→ 端口数判 1 → 第 2 端口同款 6 条 → BSRR 写（第 2 端口）
→ 4×NOP（建立裕量）→ CLK=1 → 2×NOP → CLK=0 → 循环尾 3 条
```

| 项 | 值 |
|---|---|
| 每帧指令数 | `128 × M` 时钟 × 33 ≈ **4.2k**（M=1）；M=4 → 16.9k；M=11 → 46.5k |
| 每帧周期估算（1.0~1.3 周期/指令，168MHz） | ≈ **25~35µs** |
| 占 TIM3 帧周期（500µs） | M=1 **5~7%**（余量 ≈14~20×）；M=4 ≈20~28%；M=11 ≈60~80%（**余量变薄，须实测复核**） |
| 与重构前对比 | `_22_1665_scan` **指令序列逐条一致**（宿主对照脚本机器码比对，51 条指令）|

`prepare` = `128 × M` 个时钟位 × 4 条线查表（M=1 → 512 次 ≈ 数 µs；M=11 → 5632 次 ≈ 数十 µs），
在帧周期内仍有余量；
脏矩形只用于判「有无变化」，任何提交都整帧重算（避免链位散落全屏时的反查复杂度）。
