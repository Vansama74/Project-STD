# 动态滚动显示实现记录（app_scroll）

> 2026-09-07：通用动态滚动模块 `app_scroll` 落地并接入安徽费显协议 0x86~0x89 动态显示。
> 模块：`Application/Inc/app_scroll.h` + `Application/Src/app_scroll.c`；
> 渲染辅助导出：`app_render_draw_glyph_clipped` / `app_render_glyph_width_px`（`Application/Src/app_render.c`）。

## 1. 目标与语义（用户裁决 2026-09-07）

- **循环滚动**：文本按指定方向持续滚动，收到停止帧才停；越过边界后从另一侧重新进入，永不自动停。
- **方向映射**（安徽运动模式字节 → 枚举，值对齐零转换）：
  | mode | 方向 | 枚举 |
  |------|------|------|
  | 01 | 从右往左 | `SCROLL_DIR_LEFT` |
  | 02 | 从左往右 | `SCROLL_DIR_RIGHT` |
  | 03 | 从下往上 | `SCROLL_DIR_UP` |
  | 04 | 从上往下 | `SCROLL_DIR_DOWN` |
  | 00 / 全 0 帧 | **冻结该行**（2026-09-09 修订，原「停止即清行」） | `app_scroll_stop(row)` |

  > **2026-09-08 权威文档核对**：`2026-S304 费显通信协议.doc` 第 8 节仅给运动模式
  > 示例值 01，**未定义取值含义表**——1~4 方向映射为用户拍板约定，待联调校准
  > （doc/13 §8 #11）。同时文档确认：速度 1B ×2ms、停留时间 2B ×100ms 大端
  > （帧例「00 10」=1.6s）、停止帧=数据长 4 全 0、命令 86~89=第 1~4 行、行首
  > Y=00/10/20/30（**16 点阵行高口径**）——安徽接线与文档一致（doc/13 §1.1）。
  > **2026-09-09 字号裁决**：动态/静态显示改 FONT_24，动态行区域 Y=row×24/h=24
  > （行首 00/18/30/48 为按字号推导的假设，doc/13 §8 #13 待联调）。
- **停止语义（2026-09-09 修订，用户裁决）**：
  - `app_scroll_stop(slot)` = **冻结**：置槽位非活跃、**不清行、不提交**——像素停在
    当前位置静态显示；render 锁保证在途渲染完成后才返回（无半帧风险）。
  - `app_scroll_stop_all()` / `app_scroll_stop_all_nolock()` = **保持清行**（0x81 清屏
    /0x85 静态显示依赖它清掉滚动内容）——内部拆为 `_scroll_freeze_nolock`（stop 用）
    与 `_scroll_stop_clear_nolock`（stop_all 用）两条独立路径，stop_all 不继承
    freeze 语义。
- **stay_ms（停留时间）**：解析并保存于槽位，**v1 忽略**——字段口径（2B ×100ms
  大端）已由权威文档确认，但「停留」行为文档未定义（每字停留？周期间暂停？），
  语义待定（doc/13 §8 #10）。
- **屏幕口径**：尺寸无关——行区域矩形由调用方给出 (x,y,w,h)，start 时以
  `dev_display_get()` 的 `screen_rows`（=宽，命名反直觉）/`screen_cols`（=高）钳位，
  不硬编码任何屏宽。
- **通用性**：模块不含安徽专用语义；LDI/VMS 复用前把文本转 GBK 即可（安徽 ANSI=GBK 直通）。

## 2. 实现机制

```
scroll_task（惰性创建，栈 256×4=1KB，osPriorityNormal，ucHeap）
  ├─ 全槽空闲：osEventFlagsWait(WAKE, forever) 休眠 → 零 CPU
  ├─ 有活动槽：osEventFlagsWait(WAKE, 2ms 超时) → 基础节拍 2ms
  └─ 每拍对活跃槽：
        acc_ms += 2；acc_ms >= step_ms 时单步推进 1px（acc_ms -= step_ms）
        推进 = 位移 off ±1；越过边界后跳回另一侧重新进入（循环滚动）；
        回绕目标 = 对侧边缘内 1px（2026-09-08 修订，原为目标整行不可见位置，
        产生 1×step_ms 整行黑拍——周期内可见黑闪，现已消除）
        渲染 = dev_display_fill(rect, BLACK) 清行
               → 逐字形 app_render_draw_glyph_clipped(gx, gy, rect 裁剪)
               → 整拍结束 dev_display_commit_frame_rect(并集矩形) 一次（④a 2026-09-08）
  ├─ 「渲染+commit」整段持渲染互斥 s_render_mutex（⑤ 2026-09-08，与安徽静态渲染串行）
  └─ stop：冻结（置非活跃、不清行不提交，2026-09-09）；stop_all：清行后
     commit_frame_rect（④a）；公共函数自持渲染互斥，持锁调用方（安徽 0x81/0x85）
     用 app_scroll_stop_all_nolock 防重入死锁
```

**④a 脏矩形提交（2026-09-08）**：tick 对当拍推进的活跃槽取矩形**并集包围盒**（相邻
合并不必精细），整拍仅一次 `dev_display_commit_frame_rect(d, ux,uy,uw,uh)`；无活跃槽
推进则不提交（无变化），并集无效（防御路径）回退全量 `dev_display_commit_frame`。
`stop` 清行提交同样用矩形。scan_task 侧经 dev 基类 `dirty_rect_*` 字段把矩形传给
`ops->prepare`（虚表签名不变），1-263/1-969 的 prepare 只重排矩形覆盖的逻辑行
（prepare 按整行拷贝，行内 x 范围不影响布局），矩形无效走全量路径（保守回退）；
`commit_frame_rect` 对未消费的多次提交自动合并包围盒（stop_all 连续多槽提交不丢
中间清行）。收益：量产 224×128 口径每步全屏 prepare（±30~50% 亮度抖）→ 只重排
滚动行带，亮度抖消除。

**⑤ 渲染互斥（2026-09-08）**：scroll_task 的「渲染+commit」整段持 `s_render_mutex`
（`app_scroll_render_lock`/`app_scroll_render_unlock`，与槽位锁 s_scroll_mutex 分离，
惰性创建），安徽 0x81 清屏/0x85 静态显示/0x82/0x83 点命令的「stop_all + 渲染 +
commit」整段持同一锁 → 静态渲染与滚动渲染串行，消除混合帧黑条。锁序固定
**render → slot**（start 仅持 slot 不持 render，无反向获取路径 → 无死锁）；
stop/stop_all 公共函数自持渲染互斥，锁内调用用无锁变体 `app_scroll_stop_all_nolock`。

**位移边界（2026-09-08 修订）**：`off` 稳态范围——
- LEFT/RIGHT：`-(extent_w-1) ↔ w-1`（原 `-extent_w ↔ w`，含 1 拍文本整体不可见）；
- UP/DOWN：`-(font_size-1) ↔ h-1`（原 `-font_size ↔ h`，含 1 拍文本整体不可见）。
回绕直落首可见位置（1px 露对侧边缘），循环滚动视觉连续、无整行黑拍。
`app_scroll_start` 的初始位移仍为整体不可见位置（LEFT=w / RIGHT=-extent_w /
UP=h / DOWN=-font_size），首个推进拍即进入 1px 可见——初始入场语义不变。

- **步进间隔**：`step_ms = speed×2`（安徽 speed 字节 ×2ms），最小钳制 2ms
  （speed=0 防御）；基础节拍 2ms = 协议最小速度粒度。
- **平滑裁剪**：新增导出 `app_render_draw_glyph_clipped`：复用 app_render 静态
  内部函数 `_flash_addr`/`_packed_glyph_bytes` 读字模（`dev_storage_read`，W25Qxx
  SPI 互斥锁保护），逐像素 `dev_display_set_pixel`（屏幕边界+裁剪矩形双重判界，
  越界单点丢弃即平滑裁剪）。不提交帧，由调用方整帧后提交。
  （历史背景：2026-09-07 实现时 `dev_display_draw_bitmap` 对越界位图**整块拒绝**，
  滚动字形半出界无法复用它；**2026-09-14 起该函数已改为「按屏幕交集裁剪绘制」**
  （`dev_display.c:225-262`），但无裁剪矩形参数、不处理负坐标——滚动场景字形可整体
  位于矩形外往返滑动，故仍走本路径。两条路径边界语义现已一致：都只画可见部分。）
- **渲染优化**：整行文本在矩形外 → 只清不画；字形整体在矩形左/右缘外 → 跳过
  （省 W25 读）；后续字形均在右缘外 → 提前结束。
- **竖直方向**：单行文本沿 x 排布、整行共享 y 位移 off（在行带 h 内上下滑动；
  安徽 2026-09-09 起 h=24、FONT_24，字号为参数、无硬编码）。
- **字号参数化核对（2026-09-09）**：FONT_24 下字形宽度
  `app_render_glyph_width_px` = GBK 24px / ASCII 12px（`_glyph_width_px`：
  ASCII=size/2、GBK=size）；垂直回绕边界与初始位移均用 `font_size`（
  `-(font_size-1)` / `1-font_size`）、水平用 `extent_w`（按实际字形宽累计）；
  `app_render_draw_glyph_clipped` 按 font_size 行循环、字模 `_packed_glyph_bytes`
  FONT_24 GBK=72B（≤调用栈 128B 缓冲）。全链路参数化，无硬编码 16。

## 3. 并发与互斥

- **槽位并发**：单写者（协议任务 start/stop）×单读者（scroll_task）经 `s_scroll_mutex`
  （osMutexNew 惰性创建）串行。渲染在持锁内完成；stop=冻结（2026-09-09，不清行不提交，
  render 锁保证在途渲染完成后返回 → 屏幕保留完整帧、无半帧风险）；stop_all=清行。
- **渲染互斥（⑤，2026-09-08）**：`s_render_mutex` 串行「滚动渲染」与「安徽静态渲染」
  （scroll_task 渲染+commit 整段持锁；安徽 0x81/0x85/0x82/0x83 整段持锁）。锁序
  render → slot（单向），start 仅持 slot → 无死锁；stop/stop_all 公共函数自持渲染
  互斥，锁内调用用 `app_scroll_stop_all_nolock`。
- **冻结后残留**（2026-09-09）：并集提交只遍历**活跃槽**，冻结槽不参与 tick 渲染、
  不进并集矩形，pixel_map 中冻结内容天然保留；其他槽滚动不会触碰冻结槽矩形。
  同槽重入 start 覆盖字段后首拍 `_render_slot` 先 fill 清矩形再画，无旧内容残留。
- **W25 读互斥**：每拍读字库经 `dev_w25qxx.c` 读事务互斥锁串行（`_read` 入口加锁、
  内部 `_read_locked` 无锁供 `_write` 读-改-写复用，防自锁死锁；锁 `dev_w25qxx_rtos_init`
  sw_dev_initcall 创建，hw init 阶段 RTOS 未起时 NULL 直通）。
- **渲染 vs scan_task**：与既有 app_render 相同模式（pixel_map 写入可被 Realtime
  scan_task 的 prepare 中途抢占，半帧撕裂一帧可接受，无内存安全风险）。④a 脏矩形
  经 dev 字段传递（仅 scan_task 写、prepare 在 scan_task 上下文读，无并发）。

## 4. 内存与构建

- **静态 SRAM**：`s_slots[4]`（4×90B=360B）+ 事件/双互斥/任务句柄 16B = **376B**
  （④a/⑤ 新增 `s_render_mutex` 句柄 4B，2026-09-08 起 372→376B）；
  字模缓冲为调用栈内 128B（不入静态）。CCM 增量 0。scroll_task 栈 1KB 从 ucHeap
  （惰性创建，未启动滚动时 0 支出）。
- **dev_display_t 基类 +12B**（④a `dirty_rect_x/y/w/h` 4×uint16 + `dirty_rect_valid`
  1B + 填充；每个模组静态实例 1 份——1-263 实例带初始化器在 `.data`）；
  `dev_display.c` 待消费矩形暂存 10B（`.bss`）。名义合计 +26B，链接后经段对齐
  空隙吸收实测 data +8 / bss +8。
- 文本上限 `SCROLL_TEXT_MAX=64B`（GBK 32 汉字，费显单行足够）；链接若超 SRAM
  按 48/32B 或槽位数梯度收紧（见 doc/06-04）。
- 实测增量（2026-09-07，Makefile 1-263 单模块 32×32 口径）：text **+1912**、
  data **+0**、bss **+376**（SRAM ≈ 130536B，余量 ≈ 536B）；PROTO=CQ 同增量。
- **实测增量（2026-09-08 ④a/⑤，同口径）**：text **+672**、data **+8**、
  bss **+8**（RAM 合计 +16B）。基线：PROTO=ALL text 358364 / data 1656 /
  bss 137756；现 text 359036 / data 1664 / bss 137764（doc/06-04 已补账）。
- 收录：Makefile `SRC_APPLICATION`（app_render.c 之后）+ `.eide/eide.yml`
  Application/files（**外部编辑 yml 后须在 EIDE 中 Reload Project**）。
