# 车道通行灯抽象与实现（LaneLight）

> 2026-11-19 新增。LDI E7 通行信号灯及所有协议一律经本抽象控制车道通行灯。

## 1. 抽象（`Device/Inc/dev_lane_light.h` + `Device/LaneLight/dev_lane_light.c`）

| 项 | 契约 |
|---|---|
| 状态 | `DEV_LANE_LIGHT_RED_CROSS`（红叉/车道关闭）、`DEV_LANE_LIGHT_GREEN_ARROW`（绿箭/通行） |
| 互锁 | `dev_lane_light_set()` 先灭两路 → 按实现 `switch_delay_ms` 延时 → 点亮目标 |
| ALL_OFF | 仅抽象内部使用的切换中间态，不对外暴露 |
| 上电默认 | **红叉**（fail-safe，车道关闭）；注册发生在 RTOS 启动前，注册路径不调用 `osDelay` |
| 消费者 | LDI E7：绿→绿箭；红/黄→红叉（黄色无独立灯，按红上报）；其它协议通过同一 API |

## 2. 两种并列实现（EIDE 二选一编译）

| 实现 | 文件 | 硬件 | 死区 |
|---|---|---|---|
| 默认 | `Device/LaneLight/default/dev_LaneLight_default.c` | PD14 单路：绿箭=点亮 / 红叉=熄灭 | 0ms |
| 干接点 | `Device/LaneLight/DryContact/dev_LaneLight_DryContact.c` | S1/PE12=红叉、S2/PE11=绿箭，**高有效**；PE10 不接管 | 10ms（继电器） |

### 干接点接管顺序（无毛刺，同缅甸先例 doc/16 §14.2）

① 写「灭」电平（引脚仍为输入，只写 ODR 不驱动）→ ② 逐线摘 EXTI（不碰 PE10/其它线/NVIC）
→ ③ 切推挽输出（从稳定「灭」开始驱动）→ ④ 注册并点亮红叉。

**副作用**：SW1/SW2 输入语义失效（本板自驱电平被 `dev_key_get_state` 读到）。
含 RLS 干接点轮询的构建请相应排除 RLS（与缅甸构建同口径）。

## 3. EIDE 选择

- `.eide/eide.yml` 已加入三个文件（base + default + DryContact），并把
  `Device/LaneLight/DryContact/dev_LaneLight_DryContact.c` 放入 Base 与 Debug 两个 target 的排除表。
- **外部改 yml 后必须在 EIDE 中 `Reload Project`** 再构建。
- 切干接点版本：在 GUI 中排除 `default/dev_LaneLight_default.c`、取消排除 DryContact。

## 4. LDI 语音（F4H）修复（同日）

- 根因：`app_ldi_cmd.c` 的 1BH `case LDI_DEV_TYPE_VOICE` 为 TODO 空壳，设备层
  `ldi_device_voice_ctrl()`（USART6 TTS）从未被调用。
- 修复：解析 `Type(1B)+Length(2B 大端)+Data(N, GBK)`；`Type=00H` 按文字播报；
  `Type=01H`（语音序列）本板不支持 → 回 `CtlStatus=01H`；长度越界/为零 → 01H。
- 验证：1BH 下发 `F4 01 01 00 00 03 31 32 33`（播报“123”），预期 B1H 状态 00H 且语音板出声。
