## 2. 总则

1. **只写「函数/参数/表/字段语义」+「紧贴代码的一句话硬约束」**：注释写清
   用途、参数语义（单位/取值域/所有权）、结构体与查表字段含义，以及「改这里会怎样」的
   一句话绑定型约束。**不复述代码在做什么**（`what` 由代码自身表达）。
2. **复杂说明指向 doc**：机制推导、协议原文对照、现场实测数据、逐轮演进与裁决日期
   一律在 `doc/` 详述；源码只留**一行结论/契约 + doc 指针**。
3. **语言与标签**：中文正文 + Doxygen 英文标签（`@file` / `@brief` / `@param` / `@return` /
   `@retval` / `@note`）；**不引入** `@since` / `@version` / `@author` 等无消费者的标签。
4. **长度上限**：文件头 ≤ 10 行；函数注释标准形 ≤ 8 行（含标签）；行内注释一行。
5. **指针格式统一**：`详见 doc/NN_<目录名>/<文件>.md §x.y`（单文件文档写作 `详见 doc/NN_xxx.md §x`）。
   禁止 `见上文`、`README §…`、`doc/NN-NN` 这类相对/简写/无线索写法；**同文档自引**可写 `§x.y`。
   **源码与 doc 同标准**：doc/14、doc/15、doc/16 等文档正文内的跨文档指针同样按本格式写。
   **历史条目例外**（修订记录 / 归档段落）：保留当时写法，不改写历史记录。
6. **契约优先（收紧口径，2026-10-08）**：凡影响正确性的约束（屏体几何、引脚/极性、Flash 扇区归属、
   字节序、编译期互斥、通道掩码隔离、DMA/CCM 可达性、栈/堆放置）**只保留最高风险者**——判定标准
   = **改错会静默产生现场故障**；**每模块 4~8 条、每条 ≤30 字**，集中列在该模块主头文件的
   「契约」块（见 §7 第 3 条）；其余一律并入 doc（文件头保留 doc 指针）。
   **删前必须做 doc 迁移检查**（该事实能在对应 doc 查到才可删，见 §7 第 4 条）。
7. **禁止触碰**：真 `TODO`（占位实现）、`[待裁决]` / 待确认标记一律原样保留（可改写周边措辞，不得删除结论）。
8. **只动注释**：改写不得改变任何代码 token；`git diff` 必须只含注释行（§8.3）。
9. **移出源码的九类内容（2026-10-13 用户裁决）**——以下信息**不得**出现在业务代码注释里：
   ① 调试说明（探针/脚本用法/RTT 打印/判读表）；② 日期化历史修复记录（「2026-xx-xx 修复…」）；
   ③ 轮次叙事（「第 N 轮」「联调第 N 轮」）；④ A/B 测量与段尺寸 / md5 / elf 名 / 构建基线；
   ⑤ 踩坑故事与现场事故叙述；⑥「历史口径」「此前…已撤销」长段落；⑦ 被注释掉的代码块
   （承担「停用开关」语义的 `#if 0` / 注释调用**保留**，只留一句用途 + 恢复方法）；
   ⑧ 用户裁决日期与决定编号（保留结论本身 + doc 指针）；⑨ 与 doc 逐字重复的论证。
   **去处**：优先补进对应模块 `doc/NN_*/README.md`（文档已有者注释直接删）；无对应落点的
   直接删除（**不落库**——`.analysis/` 已于 2026-10-13 移除且禁止再建；确需留存先征得用户明确同意）。
10. **编译期断言（2026-10-13 用户裁决）**：业务代码不用 `_Static_assert` / `static_assert` 做防御——
   影响正确性的约束写成「一行契约注释（含越限后果）+ doc 指针」（§2 第 6 条、§6）。**现行 0 条**
   （原保留的 6 条例外——`Device/Display/dev_display_22_1665.c` 2 条、`Application/Src/app_dispatch.c`
   RB 表/尺寸 4 条——已按裁决执行轮全部删除）；全项目清理计数见历史记录
   `.analysis/comment_pass_20261013/report.md` §⑧ ~ §⑨（已随 `.analysis` 移除）。

## 3. 文件头（≤ 10 行）

**模板**

```c
/**
 * @file    <文件名>
 * @brief   <模块是什么（一句话，名词性职责）>
 *
 * 契约（改错静默致现场故障）：① …（≤30 字）；② …；③ …（仅本模块**主头文件**写全「契约」块）
 * 详见 doc/NN_<目录>/<文件>.md §x、§y
 */
```

**纪律**

- 行数 = `/**` 到 `*/` 的总行数，**≤ 10 行**（含 `@file` / `@brief` / 空行 / 指针行）。
- `@brief` 写「模块是什么」，不写「本文件包含…」这类目录式描述。
- **契约块只写一份**：全模块 4~8 条、每条 ≤30 字，集中在该模块**主头文件**（`.h`）的文件头；
  其余文件的文件头写「契约一览见 <主头文件> 文件头」+ 本文件实现哪几条 + doc 指针。
- **契约行准则（收紧口径，2026-10-08 refine 二轮）**：只保留「**防未来合理误改**」的绑定型约束
  （字段编码 / 极性 / 通道归属 / 跨模块字段语义 / Flash 扇区归属 / 内存放置）；**每条压成一行、
  不带日期与理由**（理由归 doc）；**删**与代码或断言重复的（链接期/编译期自证、改错即报错的）
  与「无需做某事」型说明；**收敛同义重复**——多条隔离/互斥类可合并为一条后重新编号。
- **编号是引用契约**：实现点引用「契约 N」；改动契约块必须同步全模块的 `契约 N` 引用
  （含各 `.c` 文件头的「本文件实现 …」）。
- 实现点（赋值句/调用点）只留 ≤6 字标签（如 `/* BE16 */`）或「契约 N」引用，不复述契约内容。
- **禁止**（一律移 doc）：命令表逐条列举、调试说明、日期化历史修复记录与轮次叙事、
  多个日期与裁决编号、现场日志样例、A/B 测量与段尺寸、长推导公式、与 doc 逐字重复的论证。

## 4. `.c` 函数注释模板

**标准形**（有参数或有返回值）

```c
/**
 * @brief  <一句话功能，动词开头，不复述函数名>
 * @param  <名>  <语义/单位/取值域/所有权，一句话；不重复类型>
 * @return <返回值语义；void 可省>
 * @note   <至多一条：非显而易见的 why / 副作用 / 调用时机或上下文约束>
 *         详见 doc/NN_<目录>/<文件>.md §x（复杂机制、推导、历史取舍一律外移）
 */
```

**极简形**（无参 / 无返回 / 平凡 helper）

```c
/** @brief <一句话功能> */
```

或与既有横幅等价的一行式（同文件内二选一，保持局部一致）：

```c
/* ---- <名>: <一句话功能> ---- */
```

**纪律**

- **只给公开 API（在 `.h` 中声明的函数）补缺失注释**；静态函数、平凡函数**不新增**注释
  （已有注释按模板就地压缩，不展开）。
- `@brief` 一句话，≤ 40 字，动词开头；不写「本函数用于…」套话。
- `@param` 只写语义（含义 / 单位 / 取值范围 / 内存归属），**不写类型**（签名已有）。
- 非 `void` 必写 `@return`；多错误码用 `@retval` 逐条列；布尔返回值写清 true / false 各自含义。
- 错误码类枚举/返回值若仅供调试器观察，写「供调试器观察」并给 doc 指针，不复制判读表。
- `@note` **至多一条**；多条说明应合并或外移。初始化 / 回调类函数的 `@note` 写调用时机
  （initcall 顺序、ISR 上下文、可否在 RTOS 前调用）。
- 函数体内注释：只解释非显而易见的 why（锁区间、原子窗口、越界早退、反死循环上限）；
  **删除**逐行复述代码的注释，以及调试说明 / 历史修复记录 / 踩坑叙事（§2 第 9 条）。
- 函数注释同样**不得**出现「（2026-xx-xx 修复）」「原实现…已撤销」「现场表现为…」这类表述：
  保留结论与约束，把成因、日期与故事移入对应 `doc/NN_*/README.md`（无落点则直接删除，不落库）。

## 5. `.h` 注释

- **声明级一句话**：导出函数给 `@brief`（必要时补 `@param` 一行），参数细节放 `.c` 的实现注释。
- 结构体成员用行尾 `/**< 语义/单位 */`；有**二进制兼容/布局要求**的记录（如 `app_board_net_cfg` 72B、
  LDI 记录、`0x49` 记录）必须保留偏移/尺寸/CRC 覆盖范围注释。
- **不复制** `.c` 的实现说明与判读表；复杂机制给 doc 指针。
- 枚举：成员逐行 `/**< 语义 */`；跨模块共享的枚举写清取值来源（如「与 display_color_t 恒等」）。

---

## 6. 宏 / 结构体 / 查表

- 每个宏一行说明（`/**< ... */`），写清**单位 / 取值域 / 由谁消费**。
- **契约宏必须保留约束行**：有编译期约束的（如通道上限、区域容量、帧长上限）注释里要有一行
  「越限后果」，即使 doc 里已有详述。
- 结构体 / 查表：表头一行写「表义 + 来源（现场标定/协议原文/推导）」；**数值本身不逐条注释**。
- 几何 / 映射类宏若「改它就要动 doc」，注释里写明「改这里须同步 doc/NN §x」。

## 7. 契约裁剪与 doc 迁移规则

1. **先核对落点**：逐条核对源码注释中的事实（现场实测结论、裁决日期、逐轮演进、被否决方案）
   是否已在 `doc/` 有落点（`grep` 关键字 + 抽读章节）。
2. **缺则先补 doc，按目标 doc 原生风格融入**：没有落点的，先并入对应 doc 的既有章节（优先扩充
   既有表格行/段落，必要时新增小节）；**不写过程语言**——不出现「注释规范化迁移补充」「本轮补 /
   本轮更正」这类描述本次工作的措辞，裁决日期、实测数字、段尺寸等事实照原样保留。
   指针一律写作 `doc/NN_<目录名>/<文件>.md §x.y`（§2 第 5 条）；**修订记录等历史条目不按新格式
   改写**（保留当时写法，不改写历史记录）。
3. **契约判定（收紧口径，2026-10-08）**：源码只保留**最高风险契约**——判定标准 = **改错会静默
   产生现场故障**（字节序、极性接管、正签名判据、掩码隔离、CCM 布局、帧头唯一性、扇区归属等）。
   **每模块 4~8 条、每条 ≤30 字**，集中列在该模块主头文件的「契约（改错静默致现场故障）」块；
   实现点只留短标签或「契约 N」引用（§3）。
4. **删前必查**：每删一条契约前做迁移检查——该事实必须能在对应 doc 查到（查不到先补 doc）；
   被删契约的落点逐条记入批次报告（第 6 条），**不写进 doc**。
5. **源码只留契约与指针**：其余细节（日期、实测数字、逐轮演进、反例日志）留在 doc；每个文件头
   ≤10 行，并给 `详见 doc/NN_<目录名>/<文件>.md §x` 指针。
6. **可核查映射（不落库）**：每批的「保留的契约行」与「被删契约 → doc 落点」逐条映射只在
   当批工作记录里核对（**不写进 doc 正文、不写映射表迁移说明**；`.analysis/` 已移除，记录不落仓库）。
7. 历史回归案例（含「曾经踩过的坑」结论）：结论若属最高风险契约 → 保留**一句话**（无日期、
   无叙事、无「此前/原实现」措辞）；成因、现场故事与逐轮演进归 `doc/`（**2026-10-13 裁决**：
   源码不再承载坑点故事）。

## 8. 验收标准（每批必做，缺一不可）

| # | 项 | 判据 | 工具 / 证据 |
|---|---|---|---|
| 8.1 | **改前版本可复现** | 改前源码可从 git 取回（`git show <commit>:<file>`；未提交的改动先存到仓库外） | `git show` + `md5sum` |
| 8.2 | **A/B 一致性** | 改前与改后同 flags 编译：**段级 md5 逐段一致**（排除 `.debug*` / `.comment` / `.ARM.attributes`）+ **反汇编逐行一致** + strip-debug 对象 md5 一致 | `arm-none-eabi-objdump -d` + `md5sum`（原 `scripts/ab_check_<batch>.sh` 已随 `.analysis` 移除） |
| 8.3 | **diff 复核** | 逐文件 `git diff` 仅含注释行变化（代码行零改动） | `git diff -- <file>` 人工复核（记录不落库） |
| 8.4 | **全量重编** | 段尺寸与基线**逐项一致**；告警数不增（全项目既有 = 3 条 HAL `-Wunused-parameter`） | **EIDE Rebuild**（现行 target）+ `arm-none-eabi-size -A`〔原 `make PROTO=ALL DISP=1_263 -j8 BUILD_DIR=…` 已随 Makefile 移除作废（2026-10-13）〕 |
| 8.5 | **回归对照（原「宿主脚本」）** | 原判据 = 被改模块的宿主推演 / 校验脚本全绿；**脚本设施已随 `.analysis/` 移除** ⇒ 等价判据 = §8.2 对象级 A/B + §8.4 段尺寸与告警 | 无（改用 `objdump` / `size -A`；必要时从 `069be96` 临时取回脚本在仓库外跑） |
| 8.6 | **改动记录（不落库）** | 逐文件改动概览 + 被删契约 → doc 落点映射 + 验证结果 + 遗留，只在当批核对时给出 | 无（`.analysis/` 已移除，记录不留仓库） |

**边界核查（脚本层）**：`__LINE__` / `__FILE__` 的运行时消费者（注释增删会移动行号）——
范围扫描已确认全仓仅 HAL `assert_param`（`Core/Inc/stm32f4xx_hal_conf.h:493`）一处，且被改 TU
不得含其展开（A/B 脚本附「非调试段无源码路径串」断言）；行尾反斜杠续行的注释、`a/**/b`
把注释当分隔符的写法（本仓 0 处）在改写时禁止使用。

**构建口径纪律**：基线对照一律用 EIDE 的**全量重建（Rebuild）**产物，并与被比较基线同口径；
不要拿不同 target 的输出目录互相冒充。〔历史（make 时代）〕原纪律为构建用 `BUILD_DIR=/tmp/...`、
不得覆写 `build/Debug/`（因 EIDE 与 make 共用同名产物）——**该风险随 Makefile 移除消失**（见 `doc/构建开关总表.md` §4.2）。

 *
