# 18 注释规范（Application / Device）

> **角色**：注释工程的**唯一验收依据**。后续每一批（模块级）注释改写均按本文执行、按 §8 验收；
> 批次留痕（归档 / A/B 证据 / 逐文件映射 / 报告）统一放 `.analysis/comment_pass_20261008/`。
> **落地范围（2026-10-08 用户裁决）**：仅 `Application/` 与 `Device/` 下的 `.c` / `.h`。
> **不改**：`Compiler/`、`Core/`、`Drivers/`、`Kernel/`、`Middlewares/`、`Platform/`（本轮范围外）、
> `.eide/eide.yml`、任何构建产物。
> **与代码的关系**：注释改写**只动注释**——不改代码 token、不改宏值、不改字符串字面量、不调排版；
> 机器码必须逐字节不变（§8）。

## 2. 总则

1. **只写 why / 约束 / 坑**：注释解释「为什么这样做、不这样会怎样、改哪里会踩什么」。
   **不复述代码在做什么**（`what` 由代码自身表达）。
2. **复杂说明指向 doc**：机制推导、协议原文对照、现场实测数据、逐轮演进与裁决日期
   一律在 `doc/` 详述；源码只留**一行结论/契约 + doc 指针**。
3. **语言与标签**：中文正文 + Doxygen 英文标签（`@file` / `@brief` / `@param` / `@return` /
   `@retval` / `@note`）；**不引入** `@since` / `@version` / `@author` 等无消费者的标签。
4. **长度上限**：文件头 ≤ 10 行；函数注释标准形 ≤ 8 行（含标签）；行内注释一行。
5. **指针格式统一**：`详见 doc/NN_<目录名>/<文件>.md §x.y`（单文件文档写作 `详见 doc/NN_xxx.md §x`）。
   禁止 `见上文`、`README §…` 这类相对/无线索写法。
6. **契约优先**：凡影响正确性的约束（屏体几何、引脚/极性、Flash 扇区归属、字节序、编译期互斥、
   通道掩码隔离、DMA/CCM 可达性、栈/堆放置）**必须在源码保留一行**——契约不能只存在于 doc。
7. **禁止触碰**：真 `TODO`（占位实现）、`[待裁决]` / 待确认标记、历史回归案例（血案记录）
   一律原样保留（可改写周边措辞，不得删除结论）。
8. **只动注释**：改写不得改变任何代码 token；`git diff` 必须只含注释行（§8.3）。

## 3. 文件头（≤ 10 行）

**模板**

```c
/**
 * @file    <文件名>
 * @brief   <模块是什么（一句话，名词性职责）>
 *
 * <关键约束 1：不看就会写错的那一条>
 * <关键约束 2~3：引脚/扇区/字节序/互斥/内存放置 等>
 * 详见 doc/NN_<目录>/<文件>.md §x、§y
 */
```

**纪律**

- 行数 = `/**` 到 `*/` 的总行数，**≤ 10 行**（含 `@file` / `@brief` / 空行 / 指针行）。
- `@brief` 写「模块是什么」，不写「本文件包含…」这类目录式描述。
- 关键约束 ≤ 3 条，每条一行；超过 3 条说明该拆到 doc 或拆文件。
- **禁止**（一律移 doc）：命令表逐条列举、修订/演进史、多个日期与裁决编号、现场日志样例、
  长推导公式、与 doc 逐字重复的论证。

## 4. `.c` 函数注释模板

**标准形**（有参数或有返回值）

```c
/**
 * @brief  <一句话功能，动词开头，不复述函数名>
 * @param  <名>  <语义/单位/取值域/所有权，一句话；不重复类型>
 * @return <返回值语义；void 可省>
 * @note   <至多一条：非显而易见的 why / 副作用 / 调用时机或上下文约束>
 *         详见 doc/NN_<目录>/<文件>.md §x（复杂机制、推导、历史取舍一律外移）
 */
```

**极简形**（无参 / 无返回 / 平凡 helper）

```c
/** @brief <一句话功能> */
```

或与既有横幅等价的一行式（同文件内二选一，保持局部一致）：

```c
/* ---- <名>: <一句话功能> ---- */
```

**纪律**

- **只给公开 API（在 `.h` 中声明的函数）补缺失注释**；静态函数、平凡函数**不新增**注释
  （已有注释按模板就地压缩，不展开）。
- `@brief` 一句话，≤ 40 字，动词开头；不写「本函数用于…」套话。
- `@param` 只写语义（含义 / 单位 / 取值范围 / 内存归属），**不写类型**（签名已有）。
- 非 `void` 必写 `@return`；多错误码用 `@retval` 逐条列；布尔返回值写清 true / false 各自含义。
- 错误码类枚举/返回值若仅供调试器观察，写「供调试器观察」并给 doc 指针，不复制判读表。
- `@note` **至多一条**；多条说明应合并或外移。初始化 / 回调类函数的 `@note` 写调用时机
  （initcall 顺序、ISR 上下文、可否在 RTOS 前调用）。
- 函数体内注释：只解释非显而易见的 why（锁区间、原子窗口、越界早退、反死循环上限）；
  **删除**逐行复述代码的注释。

---

## 5. `.h` 注释

- **声明级一句话**：导出函数给 `@brief`（必要时补 `@param` 一行），参数细节放 `.c` 的实现注释。
- 结构体成员用行尾 `/**< 语义/单位 */`；有**二进制兼容/布局要求**的记录（如 `app_board_net_cfg` 72B、
  LDI 记录、`0x49` 记录）必须保留偏移/尺寸/CRC 覆盖范围注释。
- **不复制** `.c` 的实现说明与判读表；复杂机制给 doc 指针。
- 枚举：成员逐行 `/**< 语义 */`；跨模块共享的枚举写清取值来源（如「与 display_color_t 恒等」）。

---

## 6. 宏 / 结构体 / 查表

- 每个宏一行说明（`/**< ... */`），写清**单位 / 取值域 / 由谁消费**。
- **契约宏必须保留约束行**：有编译期约束的（如通道上限、区域容量、帧长上限）注释里要有一行
  「越限后果」，即使 doc 里已有详述。
- 结构体 / 查表：表头一行写「表义 + 来源（现场标定/协议原文/推导）」；**数值本身不逐条注释**。
- 几何 / 映射类宏若「改它就要动 doc」，注释里写明「改这里须同步 doc/NN §x」。

---

## 7. 历史 / 契约注释的迁移规则

1. **先核对落点**：逐条核对源码注释中的事实（现场实测结论、裁决日期、逐轮演进、被否决方案）
   是否已在 `doc/` 有落点（`grep` 关键字 + 抽读章节）。
2. **缺则先补 doc**：没有落点的，先补进对应 doc 的相应章节（优先并入已有章节；必要时新增小节，
   并注明「2026-10-08 注释规范化迁移补充」+ 来源），**再**精简源码注释。
3. **源码只留一行**：迁移后源码保留「结论/契约 + `详见 doc/NN §x`」一行；细节（日期、实测数字、
   逐轮演进、反例日志）留在 doc。
4. **契约不迁移**：§2 第 6 条的契约必须在源码保留一行（doc 可另有详述）。
5. **可核查映射**：每批报告给出「被精简的源码注释 → doc 落点」逐条映射表。
6. 历史回归案例（含「曾经踩过的坑」结论）**保留结论一行**，出处细节归 doc。

### 例 1：文件头 52 行 → 10 行（`app_yn_ol_proto.h`）

**改前（52 行，节选首尾）**

```c
/**
 * @file    app_yn_ol_proto.h
 * @brief   云南治超屏协议（YN_1.3.0，`{` 帧族）公共定义
 *
 * 协议文档：《车道费额显示器通信协议》YN_1.3.0（2021-11-24，治超屏裁剪版；文档开头
 * 明示治超屏不开发语音与固定格式显示）。模块前缀 `yn_ol_` / `YN_OL_`，与云南常规
 * （`yn_`）严格区分——两者帧族相同、命令字高度重叠，属 `{` 帧族互斥关系。
 *
 * ── 帧格式（长度字段定界，**无校验**，与云南常规完全同构）──
 *   `'{'`(0x7B) + 命令字(1B) + 参数长度(1B **二进制字节值**) + 参数区(变长) + `'}'`(0x7D)；
 *   帧总长 = 参数长度 + 4。
 *
 * ── 命令表（'6'/'7'/'9' 文档明示不开发 → probe 快拒）──
 *   '1' 主机查询 → 应答 `{ '1' 01 00 }`；'2' 自检（数字 1~9 交替，无语音）；
 *   …（共 30+ 行命令表 / 字节序裁定 / 通道与波特率 / 上电效果 / 帧族纪律 / 内存纪律）…
 */
```

**改后（10 行）**

```c
/**
 * @file    app_yn_ol_proto.h
 * @brief   云南治超屏协议（YN_1.3.0，`{` 帧族）公共定义
```

### 例 2：函数头长块 → 模板形（`app_yn_ol_proto.c` `yn_ol_probe_frame`）

**改前（21 行，含 7 步判定表 + CQ 兼容路径 + 实现细节）**

```c
 * @brief  `{` 帧族帧探测（PURE 契约：只 rb_peek，无副作用、无阻塞）。
```
