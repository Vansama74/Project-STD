## 4. 〔已作废（2026-10-13 Makefile 移除）〕口径指纹 stamp 与重链接依赖（Makefile，2026-09-14 修复）

> **本节整体作废**：`Makefile` 与 `build/$(CONFIG)/.build_stamp` 机制随 2026-10-13 移除而消失；
> EIDE 的增量构建以 EIDE 自己的依赖模型为准。下文保留作历史记录（含 §4.1 采样偏差更正、§4.2 构建卫生 R1/R2/R3）。

**缺陷**：elf 的依赖原本只有 `.o` 列表——源文件列表（`PROTO` 剔除 LDI 目录、`DISP`
替换模组文件）与编译开关（`DEFINES`/`CFLAGS`）不在依赖图上。切换口径后若 elf 时间
戳更新，`make` 会跳过重链接、**静默复用上一口径的 elf**（产物与命令行口径不符）；
历史上靠「先手工删除 `build/$(CONFIG)/Project_STD.*`」规避，且删产物并不重编对象，
仍会混入上一口径的 `.o`（见 §4.1）。

**实现**（`Makefile`）：

- 生成口径指纹 `build/$(CONFIG)/.build_stamp`，内容 = `STAMP_VERSION` + `CONFIG` /
  `TOOLCHAIN` / `PROTO` / `DISP` / `FACTORY`（2026-09-28 新增：出厂测试实现二选一，
  `STD`/`MM`）/ `DEFINES` / `CFLAGS` / `LDFLAGS` /
  `MAKEFILE_CKSUM`（`cksum Makefile` 内容指纹）/ `SRC_FILES`（源列表）；
- 写入方式「先写 `.tmp` → `cmp` 比较 → 相同则丢弃、不同才 `mv`」：**内容变化才改写**
  （mtime 更新），内容相同不触碰文件 → 口径不变时增量构建照常（重复 `make` 零编译
  零链接，实测 0.1s）；
- `.build_stamp` 同时是**每个 `.o` 与 elf 的先决条件**：口径变化 → 全部 `.o` 重编译
  + elf 重链接（杜绝旧口径对象参与新口径链接），`hex`/`bin` 经 elf 联动；
- `MAKEFILE_CKSUM` 使**未来新增开关**（即使不流入 `CFLAGS`）只要改动 Makefile 就触发
  一次全量重建——新开关无需额外接线；
- 另加 `-MMD -MP` 头文件依赖（`.d` 与 `.o` 同目录，`-include $(DEP_ALL)` 引入）：
  头文件改动触发依赖它的 TU 重编译（实测 `touch app_scroll.h` → 4 个 TU 重编译 +
  重链接，第二次 `make` 零动作）；
- `.DEFAULT_GOAL := all`：stamp 规则位于 `all` 之前，若不加显式默认目标会劫持无参数
  `make`（只跑 stamp、不产 elf）。

**使用纪律（变更）**：切口径**不再需要手工删产物**；同一口径可安全重复 `make`。
`make clean` 仍删除整个 `build/$(CONFIG)`（含 stamp、`.d`）——并**连带删除 EIDE 在同
目录的构建产物**（既有行为，非本次引入）。

### 4.1 该缺陷造成的既有采样偏差（已更正）

2026-09-14 那轮四口径采样中，`PROTO=ALL` 两行是「删 elf 后 `make`、对象沿用上一
CQ 口径」的**污染态**：混入 CQ 口径对象后，`app_cq_proto.o` 的 `CQ_FAULT_SCREEN=1`
引用链把 `cq_render_fault_screen`（316B，位于 `app_cq_proto_cmd.o`）+ 两条故障屏文案
（rodata 30B）+ `app_factory_test_active`（12B）经 `--gc-sections` 保留下来，另
`cq_proto_timer_task` +56、`_udp_cq_read_port` +28（符号合计 +442 → 段面 **+416 text /
+40 rodata**）。**RAM 段（data/bss/ccmram）不受影响**，故 SRAM/CCM 账目不变。同期
两口径「改动前基线」用 `make -B`（全量重编）采样，本身干净，本轮已用干净重采逐项
复现。更正后数字见 `doc/06_SRAM内部分数据迁移/04_current_memory_occupancy.md` §7。

### 4.2 构建卫生纪律（2026-09-14 补，R1/R2/R3）

stamp 保证「切口径必然重编 + 重链接」，但**不覆盖「同一口径下共享产物被外部构建器覆写」**；
以下三条为互补纪律（实证见 
`gz_ol_udp_binding_report.md` §1-2 及本轮复核）。

**R1｜EIDE 构建覆写 `build/Debug/` 共享产物后，`make` 会静默复用 EIDE 的 elf（必须 `make clean && make`）**

- 事实：EIDE Debug 与 make **共用 `build/Debug/`**（同名 `Project_STD.elf/.hex/.bin`）。
  EIDE 构建以**更新的 mtime** 覆写这三个产物；此后若命令行口径与上一次 make 相同
  （stamp 内容不变 → `cmp` 相同 → 不触碰 stamp、mtime 不更新），`make -j8` 判定
  「elf 比全部 `.o` 与 stamp 新」→ **0 编译 0 链接**，**静默保留 EIDE 的错口径 elf**。
  **口径指纹只跟踪口径内容，无法感知「elf 被同口径产物覆写」这一 mtime-only 事件。**
  实证：2026-09-14 15:33 EIDE 产物曾落在 `build/Debug/`（同目录含 `.obj/`、`.lnp`、
  `builder.params` 等 EIDE 独有产物；其 `.ccmram` 与 make 四口径任一值均不符）。
  机理复核（本轮）：`touch build/Debug/Project_STD.elf && make -j8` → 仅补跑 objcopy
  （hex/bin 落后于被 touch 的 elf），**不重链接**、elf md5 不变。
- **⚠ 2026-09-17 晚 补充观测（口径可以不同也照样复用）**：EIDE 在 21:25 构建完成（CQ 口径 +
  `DISP=22_1665`，`.text=136904 .rodata=110768 .ccmram=19724`）后，紧接着的 `make -j8`（默认口径
  `ALL`/`1_263`）**同样 0 编译 0 链接**，其打印的 size 即 EIDE 产物尺寸——即 **EIDE 产物只要
  mtime 新于 stamp，即使口径与 make 当前口径完全不同，`make -j8` 也不会重链接**（stamp 规则
  只比 mtime，不比「elf 是哪套口径产出的」）。`make clean && make` 后恢复 make 口径
  （实测 `.text=174996 .rodata=204848 .data=1680 .ccmram=38332 .bss=124772 ._user_heap_stack=2564`）。
  ⇒ 纪律不变且更强：**EIDE 构建后必须 `make clean && make`**（或给 EIDE 配独立输出目录），
  否则「make 成功」不能证明 `build/Debug` 里是 make 口径的产物。
- 纪律：**EIDE 构建之后必须 `make clean && make`**（或给 EIDE 配独立输出目录）；
  重复 `make` 的「0 编译 0 链接 + md5 不变」**仅当最后一次构建确为 make 时**才可作为
  产物新鲜度的证据。
- 烧录前核对（`arm-none-eabi-size -A build/Debug/Project_STD.elf`；默认口径 GCC Debug
  `PROTO=ALL` `DISP=1_263` `FACTORY=STD`）：`.text=167752  .rodata=195776
  .data=1656  .ccmram=39652  .bss=124768  ._user_heap_stack=2560`（**2026-09-29 代码瘦身轮第二轮 /
  RTT 底层恢复后口径**；权威值见 doc/06-04 §8.4.4，以该处为准）；
  另外可加两条身份核对：`arm-none-eabi-nm build/Debug/Project_STD.elf | grep -E 'dev_display_(1_263|22_1703)_init'`
  （默认口径只应出现 `dev_display_1_263_init`）与 `du -h build/Debug/Project_STD.hex`（默认口径 ≈1020K，
  旧 EIDE 小口径产物 ≈664K）。任一不符即口径不对，禁止烧录。
  **`DISP=22_1665` 口径核对**（2026-09-17 **第二十七轮 = 模型 B，1×2** 基线）：`.text=172164
  .rodata=202952  .data=1672  .ccmram=39164（本模组 **3328B** = `1408×2 + 256×2`；绝对值含工作区
  他处在飞改动）  .bss=124712  ._user_heap_stack=2560`（SRAM 合计 128944B，余 **2128B**）、
  内嵌 tree 与源码树一致（tree 由 `app_boot.o` 内嵌，**改驱动后须 `make clean` 才会刷新**）；
  **烧录前核对 hex 的内容身份**（原脚本 `check_flash_artifact.sh` 已随 `.analysis` 移除，改用
  `arm-none-eabi-strings` / `arm-none-eabi-size -A` 人工核对：驱动串 `2200001665` /
  链表名 blob R1·G1·R2·G2 **与组 1 的 R3·G3·R4·G4** / **不含旧 RTT 串** / 当前树 `tree=`）——
  EIDE 与 make 共用 `build/Debug`，只看时间戳不足以判「这份 hex 是哪次构建」。

**R2｜`make -n` 干跑显示「全量过期」属预期现象**

stamp 规则带 `FORCE`（每次求值，靠 `cmp` 决定是否改写）：`make -n` **不执行配方、却假设
stamp 已被改写** → 实测输出 237 条 `gcc -c` + 1 条链接（全量过期）。真实构建因 `cmp`
判定内容相同而不触碰 stamp（mtime 不变）→ 仍为 **0 编译 0 链接**。
**不要用 `make -n` 的输出判断"是否需要重建"**，以真实 `make` 的输出与 `.o`/elf 的 mtime 为准。

**R3｜`PROTO` 无非法值守卫（已知行为，按用户裁决保持现状）**

`DISP` 有 `$(error)` 守卫（`Makefile:66-67`），`PROTO` 只对 `CQ` 做 `ifeq` 判定：
`make PROTO=bogus` **不报错、静默按 `ALL` 走**（编入 LDI + 全协议 + `-DSTD_ALL_PROTO`，
不追加 `-DPROTO_CHONGQING`），产物与 `PROTO=ALL` 等价，但 stamp 内容不同
（`PROTO=bogus`）会触发一次全量重编。**该不对称按裁决保持现状（不加守卫），仅作为已知
行为记录**：写错 `PROTO` 值不报错，需自行核对编译行是否含 `-DPROTO_CHONGQING` / LDI 源文件。

### 7.2 「按需点选」用法与口径配方

**新用法（2026-10-13 用户裁决）**：不再为每种口径建 target——需要哪些协议 / 显示驱动，
就在 EIDE GUI 里对当前 target（日常 = `Debug`；要回默认状态用 `Base`）**一步一个模块文件夹**地
「排除 / 取消排除」（排除项是虚拟路径，**必须在 GUI 勾选**，手改 yml 会被回写冲掉）。
模块私有 `-I` 已在 `incList` 里，点选后无需再加。

1. **加回某个协议模块**：从排除表里删掉 `<virtual_root>/Application/protocol/ProtocolParser_XXX`
   那一条（恢复 LDI 同理 = 删掉 `<virtual_root>/Application/protocol/ldi` 那一条，一次放开全 5 文件）。
2. **加回重庆（CQ）**：除取消排除 `ProtocolParser_ChongQing` 外，**必须同时把 `PROTO_CHONGQING`
   加回 `defineList`** —— 否则只「能收 JSON」而不含量产语义（默认 IP / TCP 端口 / CQ 业务口口径与

### 8.2 配置与 Reload 纪律

### 8.4 结构硬约束（任何口径都不得违反）

- **显示驱动 ≤ 1**：8 个 `dev_display_*.c` 同一时刻最多编 1 个（>1 = 双实例注册 + CCM 超）；
  **基类 `Device/Display/dev_display.c` 必编**；一个驱动都不编 = **无显示口径（合法）**，
  板端黑屏、运行时由 `dev_display_guard()` 兜底（doc/16 §10）。
- **出厂测试恰好 1 个**：`app_factory_test.c`（标准版）与 `app_factory_test_mm.c`（缅甸版）
  对外符号同名 ⇒ 同编即链接报 `multiple definition`，必须二选一。
- **`{` 帧族 ≤ 1**（未定义 `STD_ALL_PROTO` 时）：青海 / 山东 / 贵州常规 / 云南常规 / 四川 MTC /
  云南治超——源码事实 = 定义 `g_brace_proto_guard` 的模块，多编即链接报 `multiple definition`。
- **定义 `PROTO_CHONGQING` ⇒ 必须编重庆（CQ）模块**（否则 = CQ 语义生效但无消费者）。
- **编入模块的私有 `-I` 必在 `incList`**（防 `xxx.h: No such file or directory`）。
- **`defineList` 必含 `USE_HAL_DRIVER` / `STM32F407xx`**（基线两个）。
- 原只读校验脚本（`check_eide_targets.py`）已随 `.analysis/` 目录移除，**需自行按本条清单逐条核对**
  （与 `doc/PROJECT_MANUAL.md`「EIDE 目标口径总则」的 I1~I8 同源）。
