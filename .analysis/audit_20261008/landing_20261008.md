## 3. D3 — 代码加固（C3 的 C / D 两部分）

### 3.1 C 部分：LDI 上报 IP 单一真源（选 **b**：Sector1 为真源）

**症状（审计 C3）**：`ldi_ctx_init`（`sw_board_init` 内）早于 `app_net_boot_apply`；`PROTO_CHONGQING`
与 LDI 混编口径下前者把 `cfg.device_ip` 取成 `pl_net` 上电值 `192.168.114.200`（不写 Flash），
后者把 Sector1/netif 改成 `192.168.1.5` ⇒ **LDI 12H / D1H 报 114.200，IAP 0x01 报 192.168.1.5**。

**实现**（`app_ldi.c` + 原型 `app_ldi.h`；调用点 `app_ldi_cmd.c` 两处）：
```c
bool ldi_sync_net_from_board_cfg(void)   /* app_board_net_cfg_get() 有效且 IP 非 0 / port 1~65535
                                            ⇒ 刷新 g_ldi.cfg 的 device_ip/netmask/gateway/device_port；
                                            无效 ⇒ 保留现值返回 false */
```
调用点 = `cmd_search`（12H 搜索应答）与 `cmd_rep_ip`（D1H IP 采集应答）入口。

**为什么选 b 而不是 a**：① IAP 0x01 的真源就是 Sector1 ⇒ 读同一记录即**按构造同源**；
② 选 a（`app_net_boot` 应用后回写 LDI）会让**中立模块依赖 LDI**——无 LDI 的构建（`PROTO=CQ`、无网协议构建）
没有该符号，还得引入弱符号钩子；③ b 顺带修复第二处不一致：IAP 4B02 改 IP 后 LDI 旧缓存仍报旧值。

**未触及**：`app_net_boot` / `app_board_net_cfg` / IAP 侧零改动；装载三分支、W25 自愈、`set_remote` 语义不变；
host 字段（不在 Sector1）不参与同步。语义 = 「报配置值、重启生效」，与既定策略一致。

**验收**：LDI 12H/D1H 与 IAP 0x01 读同一记录 ⇒ **一致**（构造性保证 + 代码走查；两处调用点在对象反汇编中可核对）。

### 3.2 D 部分：通道按「是否有协议绑定」启动（推广到全部 7 条真实通道）

**实现**：`app_dispatch.c/.h` 新增只读查询
```c
bool app_dispatch_channel_has_proto(channel_id_t ch_id);   /* 越界 → false；返回 ch_proto_map[ch_id] != 0 */
```
`app_boot.c` 的 7 条通道启动各加门控：
`TCP Server / TCP Client / UDP(10011) / UDP_CQ / UDP_GZOL / RS485 / RS232`；
`app_rs232_1_start()`（USART6 语音 TX 桩，无通道任务、协议禁止 bind）**保持无条件调用**。

**推广的零回归论证（证据链）**：
1. **绑定先于启动**：33 处 `app_proto_bind_channel()` 调用点**全部**落在 `sw_app_initcall(...)` 注册的初始化函数体内
   （`.analysis/audit_20261008/landing_20261008/check_channel_gate.py` **15/15 全绿**，含 A 节逐文件花括号配对判定）；
   而所有 `sw_app_initcall` 都在 `sw_board_init()`（`init_task` 内）执行，**早于** `app_boot.c` 的通道启动。
2. **有绑定的照常启动**：四条口径实构 + 逐条核对绑定关系（下表）；协议集/显示模组的选择不影响该语义。

| 口径 | 编入的绑定方 | 被启动的通道（= 原「无条件启动」集合） |
|---|---|---|
| make `PROTO=ALL` | IAP/LDI（RJ45 槽）、CQ、GZ_OL、YN_OL、串口各协议、MM… | 7 条全启动（与原行为一致） |
| make `PROTO=CQ` | IAP + CQ + GZ_OL + YN_OL + 串口协议（LDI 已剔除） | 7 条全启动（与原行为一致） |
| EIDE Debug 等价（206 文件） | IAP + LDI + 四川 ETC/MTC/治超 | 7 条全启动（与原行为一致） |
| EIDE Myanmar 等价（207 文件） | IAP + LDI + 四川三 + MM | 7 条全启动（与原行为一致） |

3. **跳过只发生在「本来就没有消费者」的场景**：无绑定时 `app_channel_dispatch` 本就静默丢数据
   （`ch_proto_map==0` 分支；2026-09-18 前的 `[disp]` 告警已随瘦身轮删除）⇒ 不启动=少占 netconn/DMA RX，
   **不减少任何功能**；这也是审计 C7「netconn 池峰值 = 容量」的一个直接缓解（少 2 个常驻 conn 的潜在来源）。
