## 1. 根因分析

### 1.1 现场两条新观测（本轮全部推理的约束）

| 观测 | 内容 |
|---|---|
| ① | `app_default_display.c` 默认画面颜色设为 **GREEN** → **屏幕完全不显示（一点不亮）** |
| ② | 默认画面（**RED**）「口」（FONT_16 / FONT_HT）→ **只有单块模组的前 8 行**：`(3..13,3)` 11 点 + `(3,4..7)`、`(12,4..7)`、`(13,4..7)` 各 3 点 = **23 点**；**y ≥ 8 全黑** |

### 1.2 结论一句话

**第十六轮链表里的四根脚（R1/G1/B1/R2）现场只有 R1 真正导通**：R1 那条链（上半屏、红 die）工作正常，
**G1 / B1 / R2 三根脚都驱动不了任何链**。因此
**红内容只出上半屏**（下半屏那条红链的脚 —— B1 —— 没接上），
**绿内容全屏黑**（绿内容只喂给 G1/R2 两条绿链，两条都不导通；同时红链取 R 位 = 0，上半屏也「正确地」变黑）。
再结合历史证据（第十三轮六根 RGB 脚同流图案时**无任何新亮区域**、全 1 十脚同流时**整屏 16×16 全亮**）
⇒ **其余三条链的数据入口在空闲的地址脚 A/B/C/D 上**（本模组静态扫描、行址脚空闲，
板卡把行址线当数据线用 —— 第十四轮的假设由此获得现场证据）。

### 1.3 推理链（逐点复算见 `.analysis/22_1665/check_round17.py` A 段，与实测点集**逐点一致**）

按第十六轮链表逐链算「驱动给每根脚的 128 位位流」：

| 链 | 脚 | 角色 / 区域 | 红「口」的位流 | 绿「口」的位流 | 现场（只 R1 导通） |
|---|---|---|---|---|---|
| 0 | R1 | RED / 上半屏 | **23 点**（字模第 3..7 行） | **0**（红链取 R 位） | 红：23 点亮 ✓ / 绿：**整条链变黑** ✓ |
| 1 | G1 | GREEN / 上半屏 | 0 | 23 点 | **两观测都不亮** ⇒ G1 无链 |
| 2 | B1 | RED / 下半屏 | **29 点**（字模第 8..14 行） | 0 | 红：下半屏**不亮** ⇒ B1 无链 |
| 3 | R2 | GREEN / 下半屏 | 0 | 29 点 | **两观测都不亮** ⇒ R2 无链 |

- 观测② 的 23 点 = 字模第 3..7 行（含 `y=3` 的 11 点顶边、`x=3` 左 1 px、`x=12,13` 右 2 px）
  —— 字模 dump（`贵州P10双色治超屏字库`，W25Q64 地址公式）逐点吻合；**`x=12/13` 同亮是字形本身的笔画宽度**，
  不是驱动缺陷（`check_round17.py` 有专门断言）。
- 观测① 里「上半屏也一起黑了」是**逻辑自洽的正面证据**：绿字内容下红链取到 R 位 = 0，
  所以 R1 那条链整条静默；若取色 / 落点 / 区域裁剪有 bug，上半屏不会这样表现。
- 下半屏的 29 点并不是「没算出来」——驱动**确实把它发到了 B1**；屏上不出现，只能是那一脚现场没有链。

### 1.4 被排除的假设（逐条 + 理由）

| 假设 | 排除理由 |
|---|---|
| 四条链共用一帧 / 级联成一条 512 位链 | 若成立，红「口」会**同时**点亮上半与下半（现场只有上半），且复位后立刻可见 4 份内容 |
| 绿 die 不存在 / 不可驱动 | 第十三轮十脚同流时绿 LED 亮过；全 1 十脚同流能点亮整屏 |
| 数据极性反相（也能解释「绿不亮」） | 反相会把 23 点变成 105 点（整块泛亮），与实测不符 |
| 取色 / 落点 / 区域裁剪 bug | 观测① 中 R1 那条链**正确地**随绿内容变黑；观测② 的 23 点与字模逐点吻合 |
| 「x=12 与 x=13 同亮」= 驱动缺陷 | 字模右竖笔画就是 2 px 宽（左 1 px / 右 2 px） |
| 其余三链在 G2/B2 上（第十四轮的备选） | 第十三轮 0x3F（六根 RGB 脚全开）同流图案时无任何新亮区域 ⇒ 六根 RGB 脚上都没有链 |

### 1.5 残余不确定性（诚实列出）

1. **其余三条链具体挂在 A/B/C/D 的哪三根、按什么顺序** —— 本轮的默认值（A=上半绿 / B=下半红 / C=下半绿）
   是「排除法 + 最自然顺序」的**推定值，不是结论**；必须由探针 9（§4）一次烧录读全。
   24 种组合（3 选 ? 排列 × 4 种「哪根空」）在本轮无法从已有数据唯一确定。
2. **各地址脚链的落点朝向是否与本链模型一致** —— 下半屏 PCB 常整体 180° 旋转。本轮加了
   `flags` 旗标（16 组）以便一处改定，但现场未验。
3. **「其余链只对长电平有反应」这一悬空/弱耦合假设** —— 观测①②与它不矛盾（G1/B1/R2 本来就无链），
   但它也不能被这两条观测排除；判据：**烧本轮默认口径后按 TEST 全屏白，看除上半屏外还有哪块亮**
   （若全亮 ⇒ 那三根脚上有链，只是图像跟不上；若只亮上半屏 ⇒ 与 §1.2 结论一致）。
4. 帧时长仍是**指令级估算**（≈31 指令/时钟位 ≈ 24~40µs/帧），未做 DWT 实测。

## 6. 第十八轮补记（现场追加，2026-09-17 同日；**未改固件**）

> 本节只留**指针与结论摘要**，完整报告见 **`round18_explain_and_field.md`**
> （含：宿主 `.py`/`.sh` 脚本是什么、`CHAIN_PROBE` 探针逐个模式怎么用、手把手步骤、下一步动作）。

**现场追加两条观测**：③ 全屏填充**只亮上半屏（0-7 行）**；④ TEST **全屏绿 → 绿灯一颗不亮**。

**复算结论**（`check_round18.py` **30/30 通过**，产物 `round18_color_matrix.md`）：

- 全屏纯色 = 把该链的数据脚**恒定拉高**（不是位流）。当前链表下：红 → R1+B 高；绿 → A+C 高；
  黄/蓝/紫/青/白 → R1+A+B+C 高。
- ⇒ 观测③ = **B 上没有链**；观测④ = **A、C 上没有链**（恒定电平也无反应，比第十七轮「送内容无反应」更强）。
  与 §1 的结论一致，且把「其余链只对恒定电平有反应」这条解释也一并排除（对 A/B/C 不成立）。
- **与第十五轮「全 1 十脚同流 → 整屏 16×16 全亮」的差集** = **{G1, B1, R2, G2, B2, D}**
  （第十五轮驱动十根；当前默认只驱动 R1/A/B/C）⇒ 「整屏全亮」必然依赖这六根里的至少一根。
