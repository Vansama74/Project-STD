# 22-1665 驱动 · 第二十一轮诊断报告（`prepare` 逐链掩码缺陷 → 只有链 0 能亮）

> **（2026-09-17 第二十二轮整理批注）** 本文为第二十一轮当时的报告，文中引用的
> `.analysis/22_1665/round21_check.py` 已改名 **`check_round21.py`**、
> `build_round21.log` 已移入 **`archive/logs/`**（其余结论与证据均未改动）。


- 日期：2026-09-17 夜
- 结论：**B（真代码缺陷）**，且缺陷在**当前源码**里 —— `_22_1665_prepare()` 多链分支用
  `role_bit[...] & s_chain_sel[i]` 组状态字节；`role_bit` 只有 0/1，而 `s_chain_sel[i] = 1 << i`，
  于是 `1 & 2 == 1 & 4 == 1 & 8 == 0` ⇒ **状态字节永远只有第 0 位 ⇒ 只有链 0（R1）能被驱动**，
  与链表怎么标定（脚/角色/区域）**完全无关**。这就是「改了链表行为也不变」的机理。
- 改动范围：**仅** `Device/Display/dev_display_22_1665.c`（`prepare` 一行 + 文件头第二十一轮小节 + 该行注释）；
  文档/脚本另计。**未改**链表、基类、Makefile、EIDE。
- 构建口径：`make clean && make -j8 DISP=22_1665`（PROTO=ALL，GCC Debug `-Og`，`APP_DIAG_BANNER` 默认开）

## 2. 本轮的现场取证（J-Link **只读** dump，不改目标状态）

工具：`JLinkExe -device STM32F407ZG -if SWD -speed 4000`（J-Link PLUS 在 USB 上现成可用）。

| 取证 | 命令（留档） | 结果 |
|---|---|---|
| 全片 flash | `savebin /tmp/board_flash_r21.bin 0x08000000 0x100000` | 主固件 275,696 B（`0x08040000..0x080834F0`） |
| CCMRAM | `savebin /tmp/board_ccm_r21.bin 0x10000000 0x2000` | 帧状态数组 + 像素图 + chain_dst + 合并表（共 1792 B） |
| SRAM | `savebin /tmp/board_sram_r21.bin 0x20000000 0x20000` | 驱动静态量 + `dev` 结构 |

### 2.1 板上镜像的链表与运行时状态：**已是第二十轮新表** ✔

- 运行时（SRAM）：`s_out_lines = 0x01B`（R1|G1|R2|G2）、
  `s_chain_role = {RED, GREEN, RED, GREEN}`、`s_chain_sel = {1, 2, 4, 8}`、`s_chain_ok = {1,1,1,1}`；
- `_22_1665_chain_dst[4][128]`（CCMRAM）与新表**逐位一致**：4 链均为 128 位双射，
  链 0/1 落点全在 y=0..7、链 2/3 全在 y=8..15；
- flash 里的 `_22_1665_chains` 四行 = `R1/G1(上半) + R2/G2(下半)`、`flags=0`、名字指针指向 `C0..C3`；
- 镜像身份：含 `2200001665` / `[22_1665] multichain=` / `口` / `PROGRAM_CODE 9K13A127E0`，
  **无** `probe8/probe9` 标记（= 正常显示口径）、**无** make 树哈希（`no-fingerprint`，EIDE 类构建），
  尺寸 275,696 B（与 EIDE 构建日志的 `FLASH: 275696 B / CCMRAM: 1792 B` 吻合）。

⇒ **板上跑的确实是「新表 + 新代码」的构建**，所以「表没生效」这个假设**不成立**。

### 2.2 但**帧状态数组只有链 0 的位**（关键证据）

CCMRAM `0x10000000`（= `dev->hub75_buff`，由板上 `dev` 结构里的指针核对过）128 字节：

- 值域 **{0, 1}**，只有 23 个 bit0（与字模「口」**上半屏**的 23 点完全对应），**bit2 = 0**（下半屏 29 点一个都没有）；
- 同一次 dump 里 `dev->pixel_map`（`0x10000080`）却有完整的 52 点红「口」（上半 23 + 下半 29）；
- 复位后重读：**仍然是 23/0**（非暂态）。

⇒ 屏上「只亮上半屏」正是**固件自己只发出了上半屏的位流**：链 2（R2）一个位都没被置；
绿「口」时链 0（RED 角色）取绿分量 = 0、绿链的位又被掩掉 ⇒ **全黑**。三条观测同时被解释。

### 2.3 板上 `prepare` 的反汇编：与源码同构（证明缺陷在源码，不在陈旧的镜像）

板上 ops 表（`0x0806CF84`，从 `dev` 结构读出）给出 `prepare = 0x0804AA29`。反汇编显示：

- 它是 4 链**展开**版：读 4 个角色索引（`@0x20007018`）+ 4 个掩码字节（`@0x2000701C`），
  对每条链做 `and.w`（= 源码里的 `role_bit & s_chain_sel[i]`），再 `orr` 进状态字节；
- 板上 SRAM 实测：角色 = `{0,1,0,1}` ✔、掩码 = `{1,2,4,8}` ✔、`s_out_lines = 0x1B` ✔
  ⇒ **与工作区源码逐字同构**（即板上的镜像就是这份源码的构建，缺陷不是「烧错了旧镜像」）。

## 3. 缺陷与修复（`Device/Display/dev_display_22_1665.c`，一行）

```c
/* 修复前（错） */
s = (uint8_t)(s | (_22_1665_role_bit[s_chain_role[i]][c] & s_chain_sel[i]));
/*                    ↑ 只有 0/1                              ↑ 1<<i
 *   i=0 → 1&1=1 ✔ ；i=1 → 1&2=0 ✘ ；i=2 → 1&4=0 ✘ ；i=3 → 1&8=0 ✘
 *   ⇒ 状态字节只有第 0 位 ⇒ scan 只驱动链 0（R1） */

/* 修复后（对） */
if (_22_1665_role_bit[s_chain_role[i]][c] != 0U)
    s = (uint8_t)(s | s_chain_sel[i]);
```

- **为什么宿主自检没拦住**：`check_round20.py` 等脚本按**意图语义**建模
  （`st |= role_bit << i`），不是逐字核对 C 表达式 —— 58/58 全绿而现场仍黑。
  本轮新增**源码级回归断言**（`round21_check.py` §A/§C2）：既断言源码里不再出现原错误表达式，
  也用「错误语义」复算出现场两条症状作为反证。

## 5. `_22_1665_ROW_XF` 用法（源码实读）

```c
/* 三个宏（§二）：ROW = 恒等旗标；ROW_XF = 显式旗标；ROW_DST = 显式落点表（逃生口） */
#define _22_1665_ROW(nm, lmask, rl, x, y, ww, hh)              /* flags = XF_NONE */
#define _22_1665_ROW_XF(nm, lmask, rl, x, y, ww, hh, xf)       /* flags = xf */
#define _22_1665_ROW_DST(nm, lmask, rl, x, y, ww, hh, tbl)     /* flags = XF_NONE + 显式表 */

/* 旗标（可任意组合） */
_22_1665_XF_NONE=0x0  _22_1665_XF_X=0x1（块内 dx→3−dx）  _22_1665_XF_Y=0x2（块内 dy→3−dy）
_22_1665_XF_BLK_X=0x4（块列序镜像）  _22_1665_XF_BLK_Y=0x8（块行序镜像）
_22_1665_XF_ROT180 = X|Y|BLK_X|BLK_Y（下半屏旋屏最常见的组合）
```

**当前默认四行（恒等，复制粘贴用）**：

```c
static const _22_1665_chain_t _22_1665_chains[_22_1665_CHAIN_COUNT] = {
    _22_1665_ROW("C0", _22_1665_LINE_R1, _22_1665_ROLE_RED,   0U, 0U, _22_1665_SCREEN_W, _22_1665_HALF_H),
    _22_1665_ROW("C1", _22_1665_LINE_G1, _22_1665_ROLE_GREEN, 0U, 0U, _22_1665_SCREEN_W, _22_1665_HALF_H),
    _22_1665_ROW("C2", _22_1665_LINE_R2, _22_1665_ROLE_RED,   0U, _22_1665_HALF_H, _22_1665_SCREEN_W, _22_1665_HALF_H),
    _22_1665_ROW("C3", _22_1665_LINE_G2, _22_1665_ROLE_GREEN, 0U, _22_1665_HALF_H, _22_1665_SCREEN_W, _22_1665_HALF_H),
};
```

**改朝向 = 把某一行换成 `_22_1665_ROW_XF` 并补第 8 个参数**（其余不动）：

```c
    /* 链 2（下半红）180° 旋屏：整块模组倒装时的典型情形 */
    _22_1665_ROW_XF("C2", _22_1665_LINE_R2, _22_1665_ROLE_RED,
                    0U, _22_1665_HALF_H, _22_1665_SCREEN_W, _22_1665_HALF_H, _22_1665_XF_ROT180),
    /* 只要水平镜像 */
    _22_1665_ROW_XF("C3", _22_1665_LINE_G2, _22_1665_ROLE_GREEN,
                    0U, _22_1665_HALF_H, _22_1665_SCREEN_W, _22_1665_HALF_H,
                    _22_1665_XF_X | _22_1665_XF_BLK_X),
    /* 只要垂直镜像 */
    _22_1665_ROW_XF("C2", _22_1665_LINE_R2, _22_1665_ROLE_RED,
                    0U, _22_1665_HALF_H, _22_1665_SCREEN_W, _22_1665_HALF_H,
                    _22_1665_XF_Y | _22_1665_XF_BLK_Y),
```

纪律：**只有看到「字形颠倒/镜像」才改朝向**；一次只改一条链；改完记录「链号 + 现象 + 旗标」；
当前没有任何朝向证据 ⇒ `flags` 保持恒等（避免引入新变量）。改完
`make clean && make -j8 DISP=22_1665` → 烧 `build/Debug/Project_STD.hex`。
