# 22-1665 第十九轮：最小充分探针清单（现场烧录用）

- 日期：2026-09-17（第十九轮；**本轮不改任何固件源码**，只出清单 + 判读表 + 记录模板）
- 面向对象：即将去烧录并回报结果的现场操作者（不必读源码；照抄「改哪个宏 → 改成什么 → 看什么 → 记什么」即可）
- 前置结论（本轮推理前提，均已由前几轮现场与宿主复算确认）：
  1. 屏幕 = 16×16 双色（4 链 × 128 位，每链 8 片 MBI5034B，静态单扫）；
  2. **只有链 0（R1 脚 → 上半屏红）在工作**；
  3. 已排除脚：G1 / B1 / R2（送图案与恒定电平均无反应）、A / B / C（恒定电平无反应）；
  4. 其余三链嫌疑脚收窄到 **{G2, B2, D}**（D 是唯一与历史「其它区域亮过」同步的脚）；
  5. 历史矛盾：第十三/十四轮「0x3F/0x3FF 串图案无新亮区域」，而第十五轮「十脚全 1」整屏 16×16 全亮。

## 0. 本轮答案（先看这个）：只需要 3 种探针模式，加一次收尾

| 要回报的模式 | 一句话用途 | 一轮时长 | 建议的次数 |
|---|---|---|---|
| **`CHAIN_PROBE=5` + `DATA_LINES=0x3FF`** | 阳性对照：复现「十脚恒定全 1 → 整屏全亮」（第十五轮那次） | 静态（不用等） | 1 次 |
| **`CHAIN_PROBE=8` + `DATA_LINES=0x231`**（R1+G2+B2+D） | 逐脚判「真被驱动 / 只跟电平 / 无关」，并顺带二分到单脚（一次自动走完 4 根脚） | **12 s / 轮**，循环 | 1 次 |
| **`CHAIN_PROBE=9` + `PROBE9_PINS=0x230`**（G2+B2+D） | 一次读全「脚 ↔ 区域 / 颜色 / 朝向」（标定首选） | **18 s / 轮**，循环 | 1 次 |
| `CHAIN_PROBE=0`（正常显示）+ 按读数填好的链表 | 收尾复验（完整「口」/ 全屏红绿分布） | — | 1 次（结果出来后） |

**不需要**（可跳过，理由见 §5）：探针 1 / 2 / 3 / 4 / 6 / 7；重扫 A / B / C / G1 / B1 / R2；
单脚二分的那三次单独烧录（`0x201` / `0x211` / `0x221`）——探针 8 一个轮次内自动逐脚走完，等于免费二分。

> `_22_1665_CHAIN_PROBE` 默认值被留成 **`(3U)`**（注释与全部文档都写「0 = 关（默认）」）。
> 也就是说：**不动源码直接 `make` 烧录，屏上跑的是探针 3（前半链全亮），不是正常画面、也不是本清单的任何一步。**

## 1. 源码事实核对（本轮已逐条读源码确认，非凭印象）

### 1.1 十根候选脚 → 掩码位 → 十六进制 → GPIO 端口

来源：`dev_display_22_1665.c` §二（`_22_1665_LINE_*` 宏）+ `Platform/Src/pl_hub75.c` 引脚表 +
`Core/Inc/main.h` 的 CubeMX 宏（`HUB75_R1/G1/B1/R2/G2/B2/A/B/C/D`）。

| 编号 k | 脚名 | 掩码宏 | 位 | 十六进制 | GPIO |
|---|---|---|---|---|---|
| 0 | **R1** | `_22_1665_LINE_R1` | bit0 | `0x001` | **PG9** |
| 1 | G1 | `_22_1665_LINE_G1` | bit1 | `0x002` | PG10 |
| 2 | B1 | `_22_1665_LINE_B1` | bit2 | `0x004` | PG12 |
| 3 | R2 | `_22_1665_LINE_R2` | bit3 | `0x008` | PG15 |
| 4 | **G2** | `_22_1665_LINE_G2` | bit4 | `0x010` | **PB6** |
| 5 | **B2** | `_22_1665_LINE_B2` | bit5 | `0x020` | **PB7** |
| 6 | A | `_22_1665_LINE_A` | bit6 | `0x040` | PD4 |
| 7 | B | `_22_1665_LINE_B` | bit7 | `0x080` | PD5 |
| 8 | C | `_22_1665_LINE_C` | bit8 | `0x100` | PD6 |
| 9 | **D** | `_22_1665_LINE_D` | bit9 | `0x200` | **PD7** |

派生组合（本清单用到的）：
`_22_1665_LINE_ALL = 0x3FF`（十脚）；`_22_1665_RGB_LINES = 0x03F`（六 RGB 脚）；
`_22_1665_ADDR_LINES = 0x3C0`（A/B/C/D）；**嫌疑脚 G2|B2|D = `0x230`**；
**R1+G2+B2+D = `0x231`**。脚落在 3 个 GPIO 端口（PG / PB / PD）→ 每时钟位 ≤3 次合并 BSRR 写。

### 1.3 探针 4/5/6/7/8/9 实际画什么（按源码逐条）

| 模式 | 实际行为（源码口径） |
|---|---|
| 4 | 每片的第 `POS` 级（默认 3）点亮 → 屏上 8 个点（8 片各一点） |
| **5** | **128 位全 1**（掩码内每根脚**恒定高**整整一帧）→ 不亮的位置 = 未接/坏灯。**6 与 5 完全等价**（历史编号） |
| 7 | 十根候选脚**同时**各发自己的图案：一片 16 位周期内，4×4 块的点数 = `k+1`（k=0..9 → 1,2,3,4,5,6,7,8,12,16 点）。点数判据对链内位序置换不变；补色图案读 `16−点数` |
| 8 | **逐脚**：掩码内 k 升序循环，每根脚停留 3 s —— **前 1.5 s 2 Hz「全 1 帧 ↔ 全 0 帧」**（= 该脚 500 ms 恒定高 / 500 ms 恒定低），**后 1.5 s 静态 `1010…` 纹理**。R1 区（上半屏）显示**一位数字 = 当前被测脚 k**（0..9 = R1/G1/B1/R2/G2/B2/A/B/C/D）；RTT 同步打 `[22_1665] probe8 dwell: pin=… (P… ) k=…` |
| 9 | **逐链 × 逐脚**：外层链（0..3）、内层脚（`PROBE9_PINS`），每个组合 1.5 s；期间**只驱动该脚**（其余组合内脚写 0），送**该链自己区域的内容**（`pixel_map` 该链落点表处**非黑即亮**）；R1 区显示**两位数字：左 = 链号、右 = 脚号 k**；RTT 打 `[22_1665] probe9: chain=… role=… pin=… k=…`；扫完循环 |

**探针 9 一轮的时长/组合数**（本轮要用的口径 `PROBE9_PINS=0x230`）：
链 4 条 × 脚 3 根（k=4 G2 / k=5 B2 / k=9 D）= **12 个组合 × 1.5 s = 18 s / 轮**，循环播放，随时可重看。
（默认 `0x3C0` 时 = 4×4 × 1.5 s = 24 s；探针 8 用 `0x231` 时 = 4 根脚 × 3 s = **12 s / 轮**。）

### 步 0（不烧录）：核对板上镜像 + 抢到免费的阳性对照

**做什么**：给板子上电（或复位），打开 RTT，看屏。

**要看/要记**：
1. RTT 有没有 `[diag]` 行？抄下 `fw= … built= … tree= …`（**没有 `[diag]` 行 = 板上是旧镜像，先重烧**）；
2. `[22_1665] multichain=… chains=… screen=… frame_bits=…`；
3. `[22_1665] chain0..3 … lines=0x… role=… region=(…) xf=…`（`lines=0x040/0x080/0x100` ⇒ 板上是第十七轮默认口径）；
4. `[22_1665] out_lines=0x… ports=… states=…`（探针 0 默认口径应为 `out_lines=0x1C1`，即 R1|A|B|C）；
5. `[22_1665] pin=… (P…) write1/read=… write0/read=… PASS|FAIL` **逐行抄**（探针 0 口径下 = 4 行 R1/A/B/C）；
6. **屏上现在是什么**：
   - 红色「口」只在上半屏、y≥8 全黑 ⇒ **这就是「探针 0 + 红色口」的阳性对照，免费拿到**（对应 §5 里 ⑤ 的第二项）；
   - 若屏上出现「半亮的粗块状图案、无数字」而 RTT 没有 `probe8/probe9` 行 ⇒ **板上是探针 3**（源码遗留默认值），需要按步 1 重烧；
   - 其它现象 → 原样记录。

**判据**：`tree=`（镜像身份）与 `chains/lines=`（链表口径）两条对上，后面的结论才成立。

### 步 1（烧录 1）：`CHAIN_PROBE=5` + `DATA_LINES=0x3FF` —— 阳性对照 / 全体恒定高

```c
#define _22_1665_CHAIN_PROBE (5U)      /* 全链点亮：十脚恒定全 1 */
```

**预期与判读**：

| 屏上看到 | 结论 | 下一步 |
|---|---|---|
| **整屏 16×16 全亮**（上半 + 下半、含绿）——即复现第十五轮那次 | 板子/接线/镜像与当时一致；**「其余三链能被点亮」这一前提成立** | 走步 2 |

### 步 2（烧录 2）：`CHAIN_PROBE=8` + `DATA_LINES=0x231` —— 逐脚闪烁 + 纹理（一次自动二分）

```c
#define _22_1665_CHAIN_PROBE (8U)
#define _22_1665_DATA_LINES   (0x231U) /* R1 + G2 + B2 + D（R1 兼作序号显示器 + 阳性内对照） */
```

构建 → 烧录 → 上电。**一轮 12 s，循环**：k=0(R1) → k=4(G2) → k=5(B2) → k=9(D) → 回到 k=0。

**每一根脚停留 3 s 内应看到两段**：先 1.5 s「整块亮 / 整块灭」2 Hz 闪烁，再 1.5 s 静态细密纹理。
上半屏同时显示**一位数字 = 当前被测脚号 k**（RTT 也会每 3 s 打一行 `probe8 dwell: pin=… k=…`）。

**判读（对每个 k 填一行）**：

| 现象 | 结论 | 填表 |
|---|---|---|
| 数字 = k，某区域**闪 + 后段细密纹理** | 该脚**真驱动**了一条链 | 记区域 + 闪烁段的**颜色**（红/绿）+ 纹理是否规则 → 该链的 `line_mask = 1<<k` |
| 数字 = k，某区域**只闪、纹理段什么都没有** | 该脚与链之间只是「电平跟随」（悬空/弱耦合） | 不能做正式数据线；记录并回报 |
| 数字 = k，别的区域**全程无反应** | 该脚不与任何链相连 | 该脚排除 |
| **k=0（R1）**：上半屏闪 + 纹理 | **内对照通过**（屏幕/驱动/探针机制都活着） | 继续进行 |
| k=0 都无反应 | 镜像/驱动异常，后面结论不成立 | 停下回报 |

**为什么这一步等于「二分」**：探针 8 一轮里逐根脚单独驱动（其余脚主动写 0），所以「哪根脚对应哪块屏」
不用再单独烧 3 次去试（round18 §4.2 的 `0x201/0x211/0x221` 三个子步都可以省掉）。

### 步 3（烧录 3）：`CHAIN_PROBE=9` + `PROBE9_PINS=0x230` —— 逐链 × 逐脚内容扫描（读全表）

```c
#define _22_1665_CHAIN_PROBE (9U)
#define _22_1665_PROBE9_PINS  (0x230U) /* 只扫 G2 / B2 / D（A/B/C 已由恒定电平排除） */
```

构建 → 烧录 → 上电。**一轮 18 s，循环**（4 链 × 3 脚 × 1.5 s）：
链 0→(G2,B2,D) → 链 1→(G2,B2,D) → 链 2→… → 链 3→…，然后重复。
屏上：上半屏显示**两位数字（左 = 链号 0..3、右 = 脚号：4=G2 / 5=B2 / 9=D）**。

**先给屏上放一幅「铺满」的画面当内容**（否则下半屏区域可能没有内容可送）：
按 TEST 键 **2 次**（第 1 次 = FW/MD 文字，第 2 次 = **全屏红**）→ 此后每个被测链的内容都是「全 1」，
被测脚那条链应当**整块亮**。

**判读（每 1.5 s 一组）**：

| 看到 | 结论 |
|---|---|
| 某块屏出现**整块亮**（全屏红内容下） | 该「链号 × 脚号」成立：**该链 = 该脚**；**颜色 = 该链 die 的颜色**（红/绿） |
| 亮块出现在**上半屏** | 该链覆盖上半屏 → `region = (0,0,16,8)` |
| 亮块出现在**下半屏** | 该链覆盖下半屏 → `region = (0,8,16,8)`（左/右半同理 `(0,0,8,16)` / `(8,0,8,16)`） |
| 想读**朝向/镜像**：把画面换成一幅**不对称**图案（TEST 第 11 次进老化、或第 9/10 次的中文两行），重看一轮 | 字符上下颠倒 / 左右相反 ⇒ 该链加 `flags`（最常见 `_22_1665_XF_ROT180`；水平镜像 `X|BLK_X`、垂直镜像 `Y|BLK_Y`） |
| 扫完全部组合**什么都不出** | 这三根脚都不通向其余链（或需要「使能 + 数据」两脚组合，当前固件测不了）→ 走 §4 决策树的「全黑分支」 |

**注意**：探针 9 的两位数字始终显示在**上半屏**（由 R1 承载，与链 0 区域绑定）；被测链的内容出现在它自己的区域。

## 3. 决策树（一页版）

```
步 0 核对镜像（不烧）
 ├─ 无 [diag] 行 / 屏上是「半亮粗块」→ 先按步 1 重烧
 └─ 有 [diag] + 红色口只在上半屏 → 免费拿到「探针 0 阳性对照」，继续

步 1  probe=5 @ 0x3FF（十脚恒定高）
 ├─ 整屏 16×16 全亮（复现第十五轮）
 │     → 锚点成立，走步 2
 ├─ 只有上半屏亮
 │     → 拍照 + 回报；仍走步 2（此时步 2/3 的负结果要按「板子已变」重新解释）
 └─ 全黑 / 上半屏也不亮 → 停下回报（贴 RTT）

步 2  probe=8 @ 0x231（逐脚闪 + 纹理；12 s 一轮）
 ├─ k=0(R1) 闪 + 纹理（内对照过）→ 看 k=4/5/9：
 │    ├─ 某 k：闪 + 细密纹理  → 该脚真驱动一条链 → 记「区域 + 颜色 + 是否规则」→ 走步 3 读数
 │    ├─ 某 k：只闪无纹理    → 只跟电平（弱耦合）→ 记下，回报（该脚不能做数据线）
 │    └─ k=4/5/9 全无反应    → 走步 3（内容扫描做最后确认），若步 3 也无 → 走「全黑分支」
 └─ k=0 也无反应 → 停下回报（镜像/驱动异常）

步 3  probe=9 @ 0x230（逐链×逐脚内容；18 s 一轮；先 TEST×2 = 全屏红）
 ├─ 某「链号 × 脚号」出整块亮 → 填该链 line_mask/role/region（想读镜像就换不对称图案再看一轮）
 │     → 走步 4 收尾

         ① 用 probe=5 + DATA_LINES=0x230（三根嫌疑脚**同时**恒定高）再烧一次：
              有区域亮 ⇒ 其余链需要「两根以上同时为高」（典型 = 一根使能 + 一根数据）
              （注意：步 1 的 0x3FF 若已亮过，那条已提示「至少一根在 {G1,B1,R2,G2,B2,D} 里」）
              仍无 ⇒ 数据入口不在 MCU 侧这 10 根脚上 → 硬件侧（排线/缓冲芯片/照片）
         ② 需要「A 常高 + B 送内容」这类组合时，当前固件**结构上测不了** —— 下一轮加
            「扫描期间常高脚掩码」（round18 §4.6 已给建议 diff），不在本次烧录范围

步 4  probe=0 + 填好的链表（收尾复验）
 ├─ 完整「口」+ 全屏红/绿分布正确 → 完成
 └─ 某块颠倒/镜像 → 加 flags 再烧一次 → 完成
```

## 5. 明确可以跳过 / 不需要烧的口径与理由

| 跳过的口径 | 为什么不烧 |
|---|---|
| 探针 1（走点） | 用于读「链位在屏上的排列顺序」；只在链已知能出内容时才有意义，且慢（12.8 s 一轮）。探针 8/9 已覆盖 |
| 探针 2（区间全亮）/ 4（片锚点） | 都用于读**已知能工作的链**的块形状；链 0 的模型（第十二轮反解）已经确认，其余链还没证明能出内容 |
| 探针 3（前半链全亮） | 5 的弱化版（只亮 128 位里的前 64 位）；无新信息。**但它现在恰是源码里的遗留默认值，必须改掉** |
| 探针 6 | 与 5 **完全等价**（历史编号） |
| 探针 7（逐脚标识） | 十根脚同时发图案，可一次读出脚号，但**分不清「真被驱动」与「只跟电平」**，且若其余链对位流无反应就是全黑（无信息）。探针 8（逐脚 + 纹理）+ 探针 9（逐脚 + 内容）严格更强 |
| 重烧 A / B / C / G1 / B1 / R2 的单独口径 | 它们已被「全屏纯色 = 恒定高」的口径排除（红/黄/白把 A/B/C/B 拉高、绿把 A/C 拉高，屏上其它区域均无反应）。**关键论证**：一帧内 128 个 CLK 照常发出、只有数据电平不同 ⇒「恒定全 1」是链能收到的**最大激励**（整条链全亮）；若它都点不亮，任何位流内容都不可能点亮（除非该脚只是「弱耦合电平跟随」，那正是探针 8 判据） |
| round18 §4.2 的三次单脚二分（`0x201` / `0x211` / `0x221`） | 探针 8 一轮内自动逐脚驱动（其余脚写 0），等价于免费二分，省 3 次烧录 |
| 探针 5 + `DATA_LINES=0x231`（三根嫌疑脚同时高） | 被步 1 的 `0x3FF`（十脚高，**包含**这三根）覆盖。只有一种情况值得单独烧：步 1 整屏全亮、但步 2 逐脚全无反应（= 需要「两根以上同时为高」）→ 那时它是「全黑分支」的第 ① 步 |
| 多链兼容口径（`MULTI_CHAIN=0`） / `BLK_COLS` 变体 / `DATA_ACTIVE_HIGH` 反转 | 本轮问题是「哪根脚管哪条链」，与历史兼容口径无关；极性反转只在出现**补色**（该亮的灭、该灭的亮）时才需要，可作为最后手段 |
| **每次都必须显式写宏值** | 因为源码默认 `CHAIN_PROBE=3`（见 §0 警告）；不写就等于烧了探针 3 |
