## 与「第十五轮 十脚全 1 → 整屏全亮」的差异

- 口径 B（第十五轮那次）：驱动 ['A', 'B', 'B1', 'B2', 'C', 'D', 'G1', 'G2', 'R1', 'R2']（十根，恒定全 1）→ 整屏 16×16 全亮；
- 当前默认（口径 D）：驱动 ['A', 'B', 'C', 'R1']（四根；其余六根恒低）→ 只亮上半屏；
- 差异 = ['B1', 'B2', 'D', 'G1', 'G2', 'R2'] ⇒ **整屏全亮依赖这六根里的至少一根**。

> **相关性**：唯一「在阳性口径里被驱动、在全部三个阴性口径里都恒低」的脚 = **D**（其它脚都至少在一个阴性口径里被驱动过）。
> 集合代数：三条阴性口径各自要求「需要的脚集 N」含有 {A,B,C,D} 之一（口径 A 否定）、{D,G1,B1,R2,G2,B2} 之一（口径 D 否定）、{G2,B2,D,A,B,C} 之一（口径 C 否定）⇒ **单脚解唯一 = D**；两脚解如 {A, G2} 也自洽（一根数据 + 一根使能/选通）。

## 推荐动作

| 步 | 宏 | 一轮时长 | 判据 |
|---|---|---|---|
| 0. 复核镜像身份 | 不改，看 RTT 横幅 `tree=` / `chainN … lines=` | — | 确认板上跑的确实是第十七轮默认口径 |
| 1. 复核「除上半屏外还能亮吗」 | `CHAIN_PROBE=5` + `DATA_LINES=0x231`（R1+G2+B2+D） | 恒定 | 有别的区域整块亮 = G2/B2/D 里至少一根通向其余链（或 D 是使能脚）；只上半屏 = 这三根也不行 |
| 2. 二分 D | `CHAIN_PROBE=5` + `DATA_LINES=0x201`（R1+D） | 恒定 | 有别的区域亮 = D 单独就够（数据脚）；仍只上半屏 = D 不是单独数据脚（可能要使能+数据） |
| 3. 区分真驱动 / 只跟电平 | `CHAIN_PROBE=8` + `DATA_LINES=0x230`（G2/B2/D） | 9s | 闪 + 细密纹理 = 真被驱动；只闪无纹理 = 只跟电平；无反应 = 无链 |
| 4. 读全表（脚/颜色/区域/朝向） | `CHAIN_PROBE=9` + `PROBE9_PINS=0x230` | 18s | 某块屏出现形状正确的内容 → 填该行 `line_mask`/`role`/`region`；镜像则加 `flags` |
| 阳性对照 | `CHAIN_PROBE=5` + 默认 0x3FF（十脚） | 恒定 | 应复现「整屏全亮」（第十五轮那次）；若复现不了，先查镜像/接线是否已变 |

> **探针 8/9 的固有局限（本轮如实记录）**：两者都是「一次只驱动一根脚」——若其余链需要「使能脚常高 + 数据脚送内容」的组合（本轮集合代数给出的两脚解），单脚探针永远看不到内容。真出现这种情况，需要下一轮加一个「常高脚掩码」参数（探针 10：`_22_1665_PROBE9_ENABLE_PINS`，扫描期间恒高）。
